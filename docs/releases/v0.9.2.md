# BeepType v0.9.2

**这一版只修一个 bug：开着「粘贴后自动发送」发图文消息时，电脑端常常只留下一个换行、消息没发出去（图越大越容易）。手机端没有改动，不用更新。**

## 电脑端

### 图文消息现在能可靠地发出去

原因：图片粘进输入框后，目标应用还要**异步把这份图读走、上传/入库**；这段时间里它能接受粘贴，但**按回车不算"发送"**，只会插入换行。图越大这段窗口越长 ⇒ 小图正常、大图翻车，看着像"不稳定复现"。

三处改动：

1. **写剪贴板前把长边压到 1920**。剪贴板里只能是位图，而主流聊天软件（Chromium / Electron 系）只接受 `image/png`（jpeg / webp / bmp / tiff 实测全部被忽略），PNG 体积正比于像素数。压到 1920 后，一张手机照片从"电脑要处理 10~16MB"降到 4~6MB，应用到"可以发送"从 1.1~1.8 秒降到约 0.9 秒；
2. **图文消息的回车会等图片消化完**：按剪贴板像素数估时（实测端到端约 4.2MB/s，再留约 45% 余量），单次最多等 4 秒；
3. 图片日志现在同时打印原始尺寸与剪贴板尺寸（`2560x3412 -> 1920x2560`），便于以后排查。

**纯文字消息完全不受影响**：没有图片就没有任何额外等待，时序与之前一模一样（已用单测钉住）。

### 一个可见的变化：贴进电脑的图片是 1920 长边

手机端发出的原图不变（仍是长边 2560 / JPEG q92），只是**写进电脑剪贴板的那一份**降到长边 1920——因为目标应用要吞的就是这份位图，尺寸直接决定了它多久能接受回车。

实测 1920 下，对着屏幕拍的照片里的等宽小字仍然清晰可读；如果你更看重分辨率，这个上限是一个常量（`CLIPBOARD_MAX_EDGE`），可以调到 2048，代价是图文消息多发前多等约 0.3 秒。

（不设 2560 的原因：最坏的方形图会超出"最多等 4 秒"的封顶，等于把这个 bug 请回来。）

## 手机端

**这一版没有手机端改动，不用更新**；只升电脑端即可。

## 已知边界（说清楚，免得误会）

- 图文消息在图片较大时，文字贴好后最多还可能等 1~2 秒才发出去（硬上限 4 秒）——这是"宁可晚一点，也不把消息丢在输入框里"的取舍；
- 若目标应用处理图片比实测更慢（例如网页版聊天还要真上传到服务器），仍可能赶不上；那种情况窗口由网络决定，任何估算都挡不住；
- 其余同 v0.9.1：GNOME / KDE 的 Wayland 不支持自动粘贴与自动发送（回退手动 `Ctrl+V`）；Wayland 的终端粘贴需要 `wtype`；图片只能贴在支持粘贴图片的输入框里；两端必须在同一个局域网。

## 安装

- **PC（推荐 `.deb`）**：退出正在运行的程序后 `sudo apt install ./BeepType_0.9.2_amd64.deb`（或 `sudo dpkg -i`）
- **PC（`.AppImage`）**：下载后赋予可执行权限直接运行；
- **手机**：无需更新。
