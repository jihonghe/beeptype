# BeeType v0.2.6

修复 v0.2.5 里"降级来的临时连接续连不生效"的 bug，并把这类漏洞用集成测试挡住。

## 修复

### 主力被解绑、降级为临时连接后，断线续连不生效

**现象**：扫码接入的临时连接断线后能自动续连，但"主力被解绑、连接降级为临时"这条路径不行——手机被系统杀掉进程后就再也回不来。

**根因**：降级路径从一开始就没有签发续连凭证。PC 端在降级时只发了一个空的 `session_downgraded` 消息，手机端手里没有任何可落盘的凭证，自然续不上。换言之：我把"临时会话"只等同于"码配对来的临时"，漏了"降级来的也是临时"。

**修复**：

- PC 端在解绑降级时**补发续连凭证**，随 `session_downgraded` 一并下发；日志会明确标注 `resume credential issued: true/false`
- 手机端收到后立刻把凭证落盘为临时会话记录，与扫码临时连接的待遇完全一致
- 协议：`session_downgraded` 增加可选 `resume_token` / `resume_expires_in`（旧端忽略未知字段，向后兼容）

## 内部

### 新增真实 TCP 的集成测试（4 个）

单测能覆盖"静态规则"，但覆盖不到"某条路径忘了做某事"——这次的 bug 就属于后者。现在 `ServerState` 对运行时泛型化，测试里可以用 tauri 的 mock 运行时**无头**起一个实例，用真实 TCP 连接扮演手机跑完整的状态机：

- 解绑降级必须补发凭证，且该凭证真的能用来续连（**已验证：把修复撤掉，这条测试立刻失败**）
- 扫码来的临时连接拿到凭证并可续连（回归护栏）
- 关闭续连时不签发任何凭证
- 伪造/陌生的续连凭证被拒，且不会占用席位

测试总数 31 个（含上述 4 个集成测试），仍然全部在 `cargo test` 里跑，CI 每次推送都会执行。

## 升级须知

- **Linux**：`sudo dpkg -i BeeType_0.2.6_amd64.deb`（装完请先退出旧进程再打开）
- **手机端**：本次有改动（接收降级时补发的凭证），请一并更新 Release 里的 APK
- 升级不影响绑定关系；PC 重启会换新配对码
