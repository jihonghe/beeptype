# BeepType v0.9.0

**这一版让电脑端在 Wayland 桌面上真正可用（Hyprland / Sway 等）：自动粘贴回来了，终端里也认得出终端了。** 另外修掉两个真机实测出来的 bug：连发多张图只到一部分、以及 AppImage 在较新发行版上"窗口一片空白"。**手机端这一版没有改动，不用更新。**

## 电脑端

### Wayland 会话下的自动粘贴与自动发送（新能力）

以前 Wayland 一律判定为"不支持自动粘贴"，只能手动 Ctrl+V。这一版改成**按合成器能力判定**：

- **Hyprland、Sway** 这类 wlroots 系合成器提供虚拟输入协议 ⇒ **自动粘贴与自动发送都能用**；
- **GNOME / KDE 的 Wayland 仍然不支持**（它们不提供这套协议）—— 那里照旧退化为"手动 Ctrl+V"，设置页会写明原因，不会让你自己猜；
- **终端里自动切 `Ctrl+Shift+V`**：Wayland 下也能认出终端了；但终端里**一律不自动回车** —— 在终端里回车是"执行命令"而不是"发送"，这个损失不可逆；
- **回车前会复核焦点**：从"粘贴完成"到"按下回车"之间有几百毫秒，如果你在这期间切了窗口，回车就不发（不会把回车送进你刚切过去的窗口）；
- **缺 `wtype` 时设置页会出现一行说明**（Wayland 的终端粘贴要用它）—— 多数 wlroots 发行版自带；没有就退化为手动粘贴，但你会知道为什么。

### 修复

- **连发多张图只到一部分（实测"选 3 张只到 2 张"）**：手机是一张等一个确认才发下一张，而电脑端一注入粘贴就立刻回确认 ⇒ 下一张的写入会把上一张顶掉（目标应用读剪贴板是异步的）。现在改成"等目标把这张读走再回确认"；
- **AppImage 在较新发行版上窗口一片空白**：打包时把构建机自带的 Wayland 库（1.20）打进了包里，与较新系统（如 1.26）不匹配会让渲染进程起不来。已从包里剔掉；`.deb` 与源码构建本来就没有这个问题；
- 顺带修掉一个既有缺陷：回车前的焦点复核**原来时机太早**，等于没覆盖"粘贴到回车"这段最危险的时间 —— 现在 X11 与 Wayland 都受保护。

## 手机端

**这一版没有手机端改动，不用更新**；只升电脑端就能拿到上面全部改进。

## 已知边界（说清楚，免得误会）

- **GNOME / KDE 的 Wayland**：不支持自动粘贴与自动发送，只能手动贴（它们不提供虚拟输入协议）；
- **Wayland 的终端粘贴需要 `wtype`**：没有它时终端退化为手动 `Ctrl+Shift+V`（文字与图片仍在电脑剪贴板里），设置页会提示；
- **图片**：只有"支持粘贴图片"的输入框能自动贴出来；需要"上传附件"的输入框不响应（图片仍在剪贴板里）；
- **连发多图的节奏会慢一点**（每张多等 0.3~1 秒）：这是"选几张就真的到几张"换来的；
- 两端必须在同一个局域网。

## 安装

- **PC（推荐 `.deb`）**：退出正在运行的程序后 `sudo apt install ./BeepType_0.9.0_amd64.deb`（或 `sudo dpkg -i`）
- **PC（`.AppImage`）**：**这一版的 AppImage 才修好"窗口空白"** —— 如果你之前下过 AppImage 发现是白窗口，换成这一版；
- **手机**：无需更新。
