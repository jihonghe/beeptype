# BeeType v0.2.5

临时连接也能"断了自动回来"了；顺带把打包 identifier 收拾干净。

## 新增：临时连接的断线续连（默认 5 分钟）

以前临时连接有个硬伤：手机被系统杀掉进程后这段关系就彻底断了——手机连电脑的 IP 都不记，只能走回电脑前重新扫码。

现在，临时手机在配对时会拿到一条**短期续连凭证**，被杀进程后只要还在窗口期内，重开 APP 就自动连回来，和主力手机一样零操作。

- **窗口是滑动的**：配对成功、心跳、发文字、续连成功都把到期时间往后推——你在用就一直有效，停手超过窗口才失效（不影响会话本身能连多久，只要连接不断就一直能用）
- **可在设置里调**：「设置 → 通用 → 临时连接断线后自动续连」，四档：关闭 / **5 分钟（默认）** / 30 分钟 / 2 小时。默认取最短，因为临时连接不是核心场景（核心是私人手机连自己的电脑、一直连着），临时主要用于访客与公共电脑
- **安全边界**：PC 端零落盘（只在内存存凭证的 SHA-256、只保留最近一条、进程退出即消失）；主人在托盘点「断开当前手机」会立刻作废；临时手机依然拿不到主力 token，也无法解绑或篡位
- **窗口过期后**：清理本地记录、回到扫码引导页，并明确提示「临时会话已过期，请重新扫码」

## 修复

- 打包 identifier 由 `com.beetype.app` 改为 `io.github.jihonghe.beetype`（原值以 `.app` 结尾，与 macOS 的包后缀冲突，Tauri 构建时会告警）

## 升级须知

- **装完请先退出旧进程再打开**：identifier 变了，新旧构建之间不共享「单实例」标识——旧进程还在跑的话，新进程会因 8765 端口被占用而起不来
- **Linux**：`sudo dpkg -i BeeType_0.2.5_amd64.deb`；绑定关系不受影响（主力手机凭 token 自动重连），PC 重启会换新配对码，临时连接需重新扫码
- **手机端本次有代码改动**（临时续连 + 过期提示），建议一并更新 Release 里的 APK

## 内部

- 协议：`hello` 新增可选 `resume` 字段，`hello_ack` 新增可选 `resume_token` / `resume_expires_in`（旧客户端忽略，向后兼容）
- 测试：Rust 单测 27 个（新增续连凭证校验、窗口边界、协议往返、`resume_ttl_min` 默认值与旧配置兼容）
- 文档：PRD 新增 FR-15 与 AC-42~45；TECH_DESIGN 更新身份模型/协议/凭证生命周期；SECURITY.md 记录这次有意的放宽
- **想快速验证过期路径**不用等 5 分钟：PC 端启动时设环境变量 `BEETYPE_RESUME_TTL_SECS=20`，窗口即被压到 20 秒（仅测试用，不进 UI）
