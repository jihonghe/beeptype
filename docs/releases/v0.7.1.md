# BeepType v0.7.1

**这一版只做一件事：把"语音发送的时机"改对——**按住语音键期间一个字都不发，松手之后整段一次发出去**。它同时修好了两类老毛病：讯飞/搜狗这类**在说话途中就逐段提交**的输入法，会把一整段话打成碎片、一段一条地发出去；以及松手之后那段"等上一秒多才出现"的延迟。**

## 手机端

### 发送时机：松手才发

- 判据从"输入法的 composing 结束"改成了**麦克风占用状态**——按住语音键期间麦克风一直被占用（连停顿 5 秒也不放），松手那一刻立刻释放；
- 于是：**录音期间一个字都不发**（中途提交多少次都不发），**松手后整段一次发出去**；
- **所有输入法行为一致**：微信输入法、豆包、讯飞、搜狗四款真机验证通过——不管它是"松手才提交"还是"边说边逐段提交"，结果都一样；
- 松手之后**该等的才等**：输入框里还有没提交的文字就等它提交（省不掉，否则会把完整的一段拆成两条），没有就立刻发；语音场景另加 1.2 秒兜底（输入法卡住时先把已有的发出去，宁可少最后半句，也不能让你觉得"说了话什么都没发生"）；
- **降级**：如果某台设备不允许我们查询"麦克风是否被占用"（部分老系统、iOS），则退回原来的行为（输入法一提交就发）——那类设备上碎片问题依旧。

### 延迟

- 不再"松手后盲等 800ms"，改成按上面这条判断；观察麦克风状态的间隔也从 500ms 缩到 150ms；
- 实测手感：**微信 / 豆包 ≈ 松手后 0.15~0.25 秒**（基本"松手即出"），**讯飞 / 搜狗 ≈ 0.6 秒**——其中约半秒是输入法自己提交慢，不是我们在等；
- 手机上直接打字（不按语音键）的行为不变。

## 电脑端

- 行为与 v0.7.0 一致，本次没有功能变化。

## 这一版试过、但没有采用的两条路（记录在案）

同时评估了"让内容不进剪贴板历史"的两条做法，真机实测后**都不采用**：

- **X11 上自己当剪贴板主人**：机制本身有效（接管后所有读取都能拒），但**对"轮询型"剪贴板管理器无效**——实测桌面环境的管理器是在内容变化后 50ms 才开始、每 50ms 轮询一次，而我们的"放行"为了粘贴必须在写入后约 1ms 打开，它的请求全落在放行之后；要挡它就得连粘贴后也不放行，那会让手动 Ctrl+V 彻底失效，与"剪贴板是兜底"冲突。
- **键盘注入**（完全不碰剪贴板）：真机实测**中文会丢字、而且不稳定**（每次丢的字不一样），准确度不可接受。

结论：剪贴板 + 粘贴仍是唯一可靠稳定的投递方式。技术细节见 `docs/TECH_DESIGN.md` §10.4。

## 安装

- **PC**：先退出正在运行的程序，再 `sudo apt install ./BeepType_0.7.1_amd64.deb`（或用 `sudo dpkg -i`）
- **手机**：直接覆盖安装 `BeepType_0.7.1_arm64.apk`，**不需要卸载**（与上一版同一把签名；版本码与测试包相同，可直接覆盖）
