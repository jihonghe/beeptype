# BeeType v0.3.0

三个小功能 + 一组修复：临时手机可一键转正、装完新版可一键重启（入口在托盘）、设置页按功能分区；并修掉 v0.2.5 里"降级来的临时连接续连不生效"的 bug 与几处界面细节。

## 新增

### 临时手机一键转正为主力

以前绑定主力只有一条路：扫码时勾选「记住这台手机」。现在多了一条：**在电脑设置 →「常用手机」里，把当前在线的临时手机设为常用**（只在主力位空缺时出现该按钮），不用重新扫码。

- 电脑生成长期凭证并推送；手机落盘后即成为常用手机，界面标签从「临时连接」变为常用
- 推送失败会**回滚绑定**，不会留下"电脑以为绑了、手机没凭据"的不一致
- 已有常用手机时不显示该按钮（需先解除绑定）

### 托盘菜单：一键重启应用 + 直达设置

托盘右键菜单新增两项：**「重启应用」**（装好新版本后点一下即可切换，不必手动退出再打开，会自动切到**新装的那个二进制**）和**「设置」**（打开窗口并直接进设置页）。

细节：重启采用"延迟 1 秒启动新进程再退出"，因为单实例机制下新旧进程重叠会让新进程自杀；启动失败会留在界面提示，不会一点就没了。重启会短暂断开手机连接——主力自动重连，临时连接在续连窗口内也会自己回来。

### 设置页按功能分区

原来的「通用」一组改成三组，顺序固定为 **粘贴与发送 → 连接行为 → 启动 → 常用手机 → 关于**：

- 粘贴与发送：接收后自动粘贴 / 粘贴后自动发送
- 连接行为：连接后自动隐藏窗口 / 临时连接断线后自动续连
- 启动：开机自动启动

之前的排序是"随手追加"造成的（新项都插在开机自启前面），现在把这条规则写进了技术文档，以后新增设置项按线归位。

## 修复

### 主力被解绑、降级为临时连接后，断线续连不生效

**现象**：扫码接入的临时连接断线后能自动续连，但"主力被解绑、连接降级为临时"这条路径不行——手机被系统杀掉进程后就再也回不来。

**根因**：降级路径从一开始就没有签发续连凭证。PC 端在降级时只发了一个空的 `session_downgraded` 消息，手机端手里没有任何可落盘的凭证，自然续不上。换言之：我把"临时会话"只等同于"码配对来的临时"，漏了"降级来的也是临时"。

**修复**：

- PC 端在解绑降级时**补发续连凭证**，随 `session_downgraded` 一并下发；日志会明确标注 `resume credential issued: true/false`
- 手机端收到后立刻把凭证落盘为临时会话记录，与扫码临时连接的待遇完全一致
- 协议：`session_downgraded` 增加可选 `resume_token` / `resume_expires_in`（旧端忽略未知字段，向后兼容）

### 降级为临时连接后，手机上主动断开不回扫码页

解绑常用手机降级为临时连接后，手机上点「断开」会停在断开态，而不是回到扫码引导页——因为降级时落盘的那条"临时续连记录"让 App 认为"还有可连目标"。

现在**手机上主动断开（或被电脑端断开）会同时作废本地续连记录**，界面如实回到扫码引导页。临时续连本身不受影响：不主动断开的话，窗口期内仍可自动连回。

### 托盘入口：每次唤起窗口都是"重新进入"

- 「重启应用」从设置页移到**托盘右键菜单**（设置页「关于」只剩版本号）；托盘新增**「设置」**直达设置页
- 三个唤起入口（托盘图标左键、「打开主窗口」、「设置」）**每一次点击都落到该入口对应的页面，且从顶部开始**——不再沿用上一次停留在哪一页、滚到哪里。此前从设置页关掉窗口后再点「打开主窗口」，会停在设置页；设置页滚到底再重新打开，还会停在原处

### 设置页「常用手机」卡不再停在已离线的手机

临时手机在线时进入设置页，随后在手机上点「断开」——卡片会一直显示那台手机和「设为主力手机」按钮，点下去才报错。现在轮询会同步刷新这张卡片，手机一断开卡片就在 1 秒内自行回到空态。

### 提示不再弹系统窗口

设置失败一类提示从 `alert()` 换成**页内浮动提示**（4 秒后自隐）：系统弹窗会带出页面 URL/标题这类实现细节，而且要用户点掉才继续。新提示只写人话，并剥掉 `Error:` 这类实现前缀。

## 内部

### 真实 TCP 的集成测试（现已 6 个）

单测能覆盖"静态规则"，但覆盖不到"某条路径忘了做某事"——这次的 bug 就属于后者。现在 `ServerState` 对运行时泛型化，测试里可以用 tauri 的 mock 运行时**无头**起一个实例，用真实 TCP 连接扮演手机跑完整的状态机：

- 解绑降级必须补发凭证，且该凭证真的能用来续连（**已验证：把修复撤掉，这条测试立刻失败**）
- 扫码来的临时连接拿到凭证并可续连（回归护栏）
- 关闭续连时不签发任何凭证
- 伪造/陌生的续连凭证被拒，且不会占用席位
- 转正端到端：推送凭证 → 用该 token 换到主力席位
- 没有连接时转正被拒

测试总数 34 个（含上述 6 个集成测试），仍然全部在 `cargo test` 里跑，CI 每次推送都会执行。

## 升级须知

- **Linux**：`sudo dpkg -i BeeType_0.3.0_amd64.deb`（装完请先退出旧进程再打开）
- **手机端**：本次有改动（接收降级凭证、接收转正推送、界面刷新、主动断开后回扫码页），请一并更新 Release 里的 APK
- 升级不影响绑定关系；PC 重启会换新配对码
