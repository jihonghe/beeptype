# BeepType v0.9.1

**这一版不新增功能，只把电脑端"闲着时的开销"压下去：托盘待命时 CPU 从约 0.6% 降到几乎测不出来（每秒唤醒次数 6.7 → 0.15），常驻内存从约 320MB 降到约 110MB。手机端没有改动，不用更新。**

## 电脑端

### 关窗即释放：常驻内存约 320MB → 约 110MB

托盘常驻是常态，但以前"关闭窗口"只是把窗口藏起来——浏览器内核（WebKit）的渲染与网络进程（合计约 150MB）会一直挂着。这一版改成**关窗即销毁**，下次从托盘唤起时重建，实测约 0.2 秒。

同时修掉一处隐形浪费：以前窗口藏起来后，界面仍在**每秒**取一次数据，而且每次都重新探测一遍桌面会话能力、重新编码一遍二维码、重新新建一次网络连接取本机地址。现在窗口不在，这些工作根本不存在。

### 空闲时几乎不耗电

- 空闲 CPU：约 0.6% → **约 0（低于测量精度）**；
- 每秒唤醒次数：6.7 → **0.15**；
- 窗口打开时那部分（每秒刷新状态）也减半：不再每次多取一份设置。

### 一个小行为变化

**第二次启动 BeepType（比如从应用菜单再点一次）现在会唤起主窗口**。以前那样点是没有反应的。

## 手机端

**这一版没有手机端改动，不用更新**；只升电脑端即可。

## 已知边界（说清楚，免得误会）

- 常驻约 110MB 指的是**窗口关着、托盘待命**时；窗口打开期间约 250MB（那是使用中，不是常驻）；
- 打开窗口比"从隐藏里恢复"稍慢一点（约 0.2 秒）——这是"关窗真的把内存还回去"换来的；
- 上面的数字是在 Linux（Hyprland / Wayland，源码构建或 `.deb`）上实测的；**AppImage 另有约 20MB 启动器开销**；Windows / macOS 同样执行"关窗销毁"，但数值未实测；
- 其余同 v0.9.0：GNOME / KDE 的 Wayland 不支持自动粘贴与自动发送（回退手动 `Ctrl+V`）；Wayland 的终端粘贴需要 `wtype`；图片只能贴在支持粘贴图片的输入框里；两端必须在同一个局域网。

## 安装

- **PC（推荐 `.deb`）**：退出正在运行的程序后 `sudo apt install ./BeepType_0.9.1_amd64.deb`（或 `sudo dpkg -i`）
- **PC（`.AppImage`）**：下载后赋予可执行权限直接运行；
- **手机**：无需更新。
