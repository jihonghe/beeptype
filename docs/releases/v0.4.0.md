# BeepType v0.4.0

**这一版没有功能改动——它把整个项目从 BeeType 彻底改名为 BeepType，一次改完、不留旧物。**

## 改名与换标

- 产品名 **BeeType → BeepType**；仓库名也从 `beetype` 改为 `beeptype`（旧链接全部 301 重定向，v0.3.0 的 Release 地址照样能打开）
- **新图标**：深蓝徽章 + 青色麦克风 → 声波 → 文字光标。PC 的窗口、任务栏、托盘、安装包与手机桌面全套换新
- **新 slogan**：手机说话，电脑落字；README 正文首句：把你说的话，变成电脑里的字
- 界面文案、通知标题、托盘提示、安装包名、可执行文件名，全部跟着换新

## 改掉的不只是"看得见的"

| 项 | 旧 | 新 |
|---|---|---|
| Linux 包名 / 可执行文件 | `bee-type` / `/usr/bin/beetype` | `beep-type` / `/usr/bin/beeptype` |
| 配置目录 | `~/.config/beetype` | `~/.config/beeptype` |
| PC 应用标识 | `io.github.jihonghe.beetype` | `io.github.jihonghe.beeptype` |
| 手机应用包名 | `com.beetype.app` | `com.beeptype.app` |
| 二维码协议 | `beetype://` | `beeptype://` |
| 环境变量 | `BEETYPE_*` | `BEEPTYPE_*` |
| 开机自启项 | `~/.config/autostart/BeeType.desktop` | `~/.config/autostart/BeepType.desktop` |

**v0.4.0 与 v0.3.0 互不兼容**（协议前缀、应用身份、配置目录全变了），所以升级要按下面走一遍。这就是"一次改到底、以后不再动"的代价。

## 升级须知

**Linux：先卸旧包再装新包**

```bash
# 先退出正在运行的旧版（托盘 → 退出）：两个版本都监听 8765，旧进程不退新版起不来
sudo apt remove bee-type
sudo apt install ./BeepType_0.4.0_amd64.deb
rm -f ~/.config/autostart/BeeType.desktop
```

- **手机端**：新包在系统里是**另一个应用**（包名变了），装完桌面会出现全新的 BeepType，旧的 BeeType 可以直接卸载
- **两端都要重新扫码配对一次**：配置目录与应用身份都换了，旧配对与设置不再沿用。旧配置仍留在 `~/.config/beetype`（不会自动迁移），确认新版正常后可以删掉
- 装完在电脑设置里把「开机自启」重新勾一次，生成新的自启项
- **Windows / macOS**：同样先卸载旧版再装新的

## 功能与 v0.3.0 完全一致

这一版只改名字与外观，没有行为改动——重试策略、判活、扫码体验、临时连接保活、托盘菜单等全部与 v0.3.0 相同（细节见 [v0.3.0 发布说明](v0.3.0.md)）。

## 内部

- **全仓零残留**：源码、配置、文档、CI、图标源里不再出现旧名（`docs/releases/v0.2.2~v0.3.0.md` 作为已发布的历史记录保留原样）
- **图标成为可复现管线**：`assets/icons/app-icon-1024.png`（母版）+ `scripts/build_icons.py`（PC 走 Tauri 官方 `icon` 子命令，Android 生成各密度方块/圆形/自适应层）
