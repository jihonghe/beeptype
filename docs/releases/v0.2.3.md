# BeeType v0.2.3

修复版：修正 Linux 任务栏（dock）显示通用图标的问题。

## 修复

### 任务栏图标不再是"两个齿轮"

**现象**：Deepin 等桌面下，BeeType 窗口出现在任务栏时显示的是系统通用图标，而不是我们的图标（托盘图标一直正常）。

**根因**（实测确认）：Tauri 的 `window.set_icon()` 在这套 GTK/tao 栈上**无效**——调用返回成功，但窗口的 `_NET_WM_ICON` 属性始终不写（立即调用、延后 2 秒调用都试过）。而桌面任务栏依赖这个属性来显示窗口图标；同机对照可以看得很清楚：Edge、ZCode 等都设了这个属性、图标正常，没设的窗口就退回通用图标。另一个因素是窗口的 `WM_CLASS` 为 `"beetype", "Beetype"`（GTK 把程序名首字母大写），与 desktop 文件里的 `StartupWMClass=beetype` 大小写不一致，于是"按 desktop 文件匹配"这条路也不通。

**修法**：不再依赖 Tauri 的接口，直接自己把属性写上——连上 X server，从 `_NET_CLIENT_LIST` 里按 `_NET_WM_PID` == 本进程、`WM_CLASS` 含 `beetype` 找到自己的窗口，把 128×128 图标按 `_NET_WM_ICON` 格式（`[宽, 高, ARGB...]`）写入。带重试，失败只记日志，不影响主流程；仅作用于 Linux/X11（Wayland 用 app_id 关联，Windows/macOS 用可执行文件图标）。

## 内部

- 新增 `winicon.rs` 模块与对应单测（图标数据格式自洽、含不透明像素；`cargo test` 现为 21 个用例）
- `docs/TECH_DESIGN.md` 的模块清单、平台差异、测试表同步更新

## 安装与升级

- **Linux**：`sudo dpkg -i BeeType_0.2.3_amd64.deb`（覆盖安装后**重启应用**才会加载新二进制）
- 升级不影响绑定关系：主力手机凭 token 自动重连；PC 重启会换新配对码，临时连接需重新扫码
- 手机端无代码改动，APK 可继续用

## 已知问题（本次未改）

窗口"配对后自动收回托盘"的行为没有变化：若你曾用托盘手动打开过窗口，本次会话内它就会被当作"控制台"不再自动收回（这是既有设计）。该行为的改进在下一版评估。
