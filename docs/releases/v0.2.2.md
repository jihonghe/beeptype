# BeeType v0.2.2

修复版：处理「粘贴 → 自动发送」这条链上的时序问题，并修正设置页显示的版本号。

## 修复

### 自动发送的回车不再抢跑

目标应用（微信桌面版、网页版聊天、网页输入框、VS Code 等 Chromium/Electron 应用）读剪贴板是**异步**的：回车如果紧接着粘贴发出，可能先于文本落地执行，结果是一句空发送。本次做了三件事：

- **同一条连接按序注入**：粘贴快捷键与回车复用同一条注入连接发出，顺序由系统保证，不再依赖两次连接之间的墙钟时间；
- **回车余量改为安全余量**：基准 250ms，长文本按每 200 字符 +1ms（上限 +500ms）。这段延迟对人不可感知，而漏发的代价是消息没出去，所以取值刻意宽松——**不按机器、不按应用做特调**；
- **回车前复核焦点窗口**：如果这段时间里你把窗口切走了，就不再发回车，避免回车落进别的窗口。文字此时已经粘贴好了，需要你自己按一下回车。

### 剪贴板写入增加读回校验

写入后立即读回比对：读到的是别的内容（典型是装了剪贴板管理器的机器）就重写一次；写入报错、或重写后仍不一致才判定失败并提示。读不回来时按原样继续——不因为"校验不了"把本来能用的粘贴挡掉。

### 设置页「关于」的版本号

之前读的是 crate 版本（一直显示 0.1.0），现在改为读取构建时的应用版本，与安装包版本一致。

## 内部

- 修复仓库单测自「硬件指纹」那版起就编译不过的问题（`cargo test` 此前从未真正跑起来过），现在 20 个用例全过；
- 文档与实现对齐：`docs/TECH_DESIGN.md` 新增「粘贴时序与残余竞态」一节，记录已被架构规避的 X11 剪贴板所有权传播竞态、仍然存在的边界，以及为什么不做按应用/按机器的特调。

## 安装与升级

- **Linux**：下载 `.deb` 后 `sudo dpkg -i beetype_0.2.2_amd64.deb` 覆盖安装即可；也可用 `.AppImage`；
- **升级不影响绑定关系**：主力手机凭 token 自动重连。PC 重启会重新生成配对码，临时连接需要重新扫码；
- **手机端本次无代码改动**（APK 仍随本版本一起产出，版本号同步为 0.2.2），手机上原有的 App 可以继续用，无需重装。

## 平台说明

自动粘贴在 Linux Wayland 会话下不可用（安全模型禁止后台进程注入按键），回退为纯剪贴板 + 手动 Ctrl+V；Windows / macOS / Linux X11 正常。
