## 1. 竞品分析

### 1.1 市场背景

PC 端语音输入是一个已被验证的真实需求。Windows 和 macOS 有系统级语音输入（Win+H / Dictation），但 Linux 桌面几乎没有可用的系统级语音输入方案。用户在 Deepseek 网页端、腾讯 CodeBar、各类浏览器等不具备内置语音输入的场景下，只能手动打字。

"手机做语音识别 → 文字同步到 PC 剪贴板 → 用户手动 Ctrl+V"是当前空白市场的最轻量解法：复用用户手机上已安装的输入法语音能力，不引入额外语音引擎，不走云端，局域网直连。

### 1.2 竞品矩阵

| 产品 | 桌面端 | 手机端 | 语音引擎 | 连接方式 | 定价 | 开源 |
|---|---|---|---|---|---|---|
| **VoiceBridge / airmic** | Linux X11 | 浏览器 | Web Speech API | WebSocket + QR | 免费 | ✅ |
| **InsertKit** | Win/Mac/Linux (Tauri) | Android (Kotlin) | AI 云端 ASR | 账号云同步 | 订阅制 | ❌ |
| **VoicePad AI** | Win/Mac | Android/iOS | 本地 Whisper | WiFi + USB | 买断 | ❌ |
| **Voicy** | 全平台 | Android/iOS | 云端 ASR | 账号 | $6.79/月起 | ❌ |
| **Invoke** | Win/Mac/Linux (Python) | 无 | 本地 Whisper GPU | 无（本机） | 免费 | ✅ |
| **BeeType（本品）** | Win/Mac/Linux (Tauri) | Android/iOS (Flutter) | 复用手机输入法 | 局域网 TCP + QR | 免费 | 计划开源 |

### 1.3 逐产品分析

#### 1.3.1 VoiceBridge / airmic

- **技术路线**：手机浏览器打开 PC 提供的 Web 页面 → 通过 Web Speech API 做语音识别 → WebSocket 传回 PC → xdotool 注入到当前焦点窗口
- **亮点**：零安装（浏览器即用）、QR 配对、开源、支持中继服务器跨网络使用
- **短板**：
  - 浏览器 Web Speech API 在非 Chrome 浏览器或非 HTTPS 环境下不可用
  - Linux 端依赖 xdotool 键注入，在部分桌面环境（如 Deepin 25 + fcitx5）被拦截
  - 不支持 Wayland
  - 浏览器方案无法做到"松手即发"——需要点击网页上的按钮控制录音
- **与本品的关系**：最接近的竞品。本品用原生 APP 替代浏览器，解决"松手即发"和 IME 复用问题；用剪贴板替代 xdotool，解决键注入兼容性问题。

#### 1.3.2 InsertKit

- **技术路线**：Tauri + Rust + React 桌面端，Kotlin Android 端，账号制云同步
- **亮点**：桌面端用 Tauri（验证了 Tauri 在此类工具中的可行性）、功能丰富（文本扩展、剪贴板历史、AI 语音）
- **短板**：
  - 订阅制，文字过云端，隐私敏感
  - 走云同步而非局域网直连，延迟受网络影响
  - 功能过重，核心语音上屏被淹没在文本管理功能中
- **与本品的关系**：技术栈选型参考（Tauri）。本品聚焦单一功能（语音→剪贴板），不做文本管理。

#### 1.3.3 VoicePad AI

- **技术路线**：各平台原生应用，内置 Whisper 模型做 100% 离线语音识别
- **亮点**：完全离线、隐私好、自带 Whisper 模型
- **短板**：
  - 不支持 Linux 桌面
  - APP 包体大（Whisper 模型内置）
  - 不复用用户已有的输入法语音能力，而是自建引擎
  - 付费产品
- **与本品的关系**：本品不自带语音引擎，复用用户手机上已有的输入法（豆包/讯飞/微信），包体更小、识别质量由用户选用的输入法决定。

#### 1.3.4 Voicy

- **技术路线**：跨平台原生 + 浏览器，云端 ASR
- **亮点**：50+ 语言、AI 重写、自动标点
- **短板**：
  - 订阅制（$6.79/月起）
  - 语音数据过云端
  - 非局域网，延迟受网络质量影响
- **与本品的关系**：本品局域网直连，零延迟、零云端成本、隐私不外泄。

#### 1.3.5 Invoke

- **技术路线**：Python CLI，本地 Whisper GPU 转录，按住鼠标侧键说话
- **亮点**：开发者向、本地 GPU、无网络依赖
- **短板**：
  - 无手机端，纯 PC 本机方案
  - 需要 GPU 才能流畅运行
  - 不复用输入法
- **与本品的关系**：本品用手机做语音识别（用户已有的输入法），不需要 PC 有 GPU，也不需要安装 Whisper 模型。

### 1.4 差异化定位

| 维度 | 竞品主流方案 | BeeType（本品） |
|---|---|---|
| 语音引擎 | 自建（Whisper/云端 ASR） | **复用用户手机输入法** |
| 连接方式 | 云同步 / 浏览器 WebSocket | **局域网 TCP 直连** |
| 延迟 | 200ms~2s（受网络/云端影响） | **<50ms（局域网直连）** |
| 安装成本 | 装 APP + 注册账号 | 装 APP + QR 扫码，无账号 |
| 隐私 | 文字过云端 / 本地 Whisper | **文字仅在手机→PC 两跳，不过云端** |
| Linux 支持 | 仅 VoiceBridge（xdotool 有坑） | **Tauri clipboard 全平台原生支持** |
| 自动粘贴 | xdotool 键注入（外部命令，兼容性差） | **内建键注入（XTest/SendInput/CGEvent）默认开启，不支持的环境自动回退剪贴板** |
| 价格 | 订阅制 / 买断 | **免费开源** |

### 1.5 竞争壁垒

1. **复用输入法而非自建引擎**：用户已在输入法中训练了识别习惯（词库、联系人、习惯用语），切换到 Whisper 等新引擎反而会降低识别准确率。本品直接用用户已有的输入法，零迁移成本。
2. **局域网直连**：零延迟、零服务器成本、零隐私风险。竞品走云同步的产品在延迟和隐私上天然劣势。
3. **剪贴板始终保底**：文字先落剪贴板再谈自动粘贴，因此即使某个桌面环境拦住了按键注入（XTEST 受限、Wayland），功能也只是退化成「手动 Ctrl+V」，不会不可用。
4. **Tauri + Flutter 技术栈**：Rust 后端保证性能和安全，Tauri 保证跨平台原生安装包，Flutter 保证移动端一致体验。InsertKit 已验证 Tauri 在同类工具中的可行性。
5. **单席位 + 单一信任关系**：一台电脑同时只服务一部手机、只长期记住一部手机；临时访客两端都不留痕，从结构上排除了越权和多端争抢。

### 1.6 市场空白结论

"安卓/iOS 原生 APP → 局域网 TCP → Linux/Win/Mac 剪贴板"这个组合在现有竞品中是空白。最接近的 VoiceBridge 用浏览器（无法实现松手即发）+ xdotool（Linux 兼容性差），InsertKit 用 Tauri 但走云同步（延迟 + 隐私）。本品占据的生态位是：

> **免费、开源、局域网、复用输入法、剪贴板同步、跨平台原生应用**

## 2. 产品概述

### 2.1 产品定义

**BeeType** 是一款跨设备语音输入工具。它让用户在手机上用自己已安装的输入法（豆包、讯飞、微信等）进行语音转文字，识别完成的文字通过局域网即时同步到 PC 的系统剪贴板，用户在 PC 上按 Ctrl+V 即可粘贴。

一句话描述：**手机说话，电脑粘贴。**

### 2.2 产品边界

**做什么：**
- 手机端 APP 接收输入法语音转文字的结果，通过局域网 TCP 发送到 PC
- PC 端后台服务接收文字，写入系统剪贴板（并默认自动粘贴到光标处）
- QR 码配对建立设备信任关系；一台电脑长期只记住一部「常用设备」，其余为临时设备（FR-11）
- 身份与凭证持久化：常用设备打开 APP 即免码重连，电脑换 IP 由凭证门控的 UDP 发现纠偏（FR-12）
- 单席位仲裁：同一时刻只服务一部手机，常用设备可手动接管被占用的电脑（FR-13）

**不做什么：**
- 不做语音识别引擎——复用用户手机上已有的输入法
- 不做文件传输
- 不做剪贴板历史管理
- 不做远程控制（鼠标/键盘/屏幕）
- 不做云端中继——纯局域网，文字不过云端
- 不做账号体系——无需注册登录
- 不把键注入当唯一路径：自动粘贴失败或平台不支持（如 Wayland）时自动降级为「仅写剪贴板 + 手动 Ctrl+V」

### 2.3 产品架构

```
┌──────────────────┐                    ┌──────────────────┐
│   手机端 (Flutter)  │                    │  PC 端 (Tauri)     │
│                    │   局域网 TCP/JSON   │                    │
│  ┌──────────────┐  │                    │  ┌──────────────┐  │
│  │  TextField   │  │   text payload     │  │  TCP Server  │  │
│  │  ↑ IME 语音   │ ──────────────────→ │  │  ↓ 写入       │  │
│  │  按住说话     │  │                    │  │  剪贴板       │  │
│  │  松手即发     │  │   ack              │  │              │  │
│  └──────────────┘  │ ←───────────────── │  └──────────────┘  │
│                    │                    │                    │
│  ┌──────────────┐  │                    │  ┌──────────────┐  │
│  │  QR 扫码配对  │  │   配对握手          │  │  系统托盘     │  │
│  │  连接状态显示  │  │                    │  │  QR 展示     │  │
│  └──────────────┘  │                    │  │  开机自启    │  │
└──────────────────┘                    │  └──────────────┘  │
                                        └──────────────────┘
```

### 2.4 技术选型

| 端 | 技术 | 选型理由 |
|---|---|---|
| PC 桌面端 | Tauri 2.x + Rust | 跨平台原生安装包、clipboard/autostart/tray 官方插件、Rust 性能 |
| 手机端 | Flutter 3.x + Dart | 编译型语言低延迟、TextField 正确实现 InputConnection 接收 CJK 文本、官方桌面端支持可复用 |
| 通信协议 | TCP + JSON 行协议 | 局域网直连零延迟、JSON 易调试、行协议简单可靠 |
| 配对方式 | QR 码（PC 展示，手机扫描） | 3 步内完成、无需输入 IP/端口；配对码为高熵一次性随机串，只随二维码下发 |
| 长期认证 | token（两端只存 SHA-256） | 常用设备免重新扫码；PC 重启、两端换 IP 都能自动连回 |
| 设备发现 | UDP 凭证门控（与 TCP 同端口） | 电脑换 IP 时手机仍能找到它，且对非常用设备设备完全隐身 |
| 自动粘贴 | enigo 按键注入 + 平台能力判定 | 默认开启零手动；Wayland 等不支持时静默回退纯剪贴板 |

### 2.5 设计原则

1. **极简**：一个功能，一条链路，零配置。用户装完即用，扫码即连。
2. **复用**：不自建语音引擎、不自建输入法、不做云端服务。只做"文字从手机到剪贴板"这一段管道。
3. **兼容**：剪贴板是所有桌面环境都支持的最低公约数，因此它始终是保底路径——自动粘贴按平台能力启用（X11 / Windows / macOS 走按键注入，Wayland 等不支持的环境静默回退为纯剪贴板 + 手动 Ctrl+V）。
4. **隐私**：文字仅在手机和 PC 两台设备间流动，不过任何第三方服务器。
5. **单一信任关系**：一台电脑只长期记住一部手机，绑定入口只在 PC 侧；临时访客拿不到凭证，也发不出有效的发现请求。

### 3.2 核心使用场景

#### 场景 1：Deepseek 网页端对话（画像 A）

> 陈先生在 Deepin 桌面上用浏览器打开 Deepseek 网页端，想输入一段长提问。他拿起手机打开 BeeType APP，手机自动弹出豆包输入法。他按住输入法的麦克风说"帮我分析一下 Rust 和 Go 在异步编程模型上的本质区别"，松手后文字立即出现在手机输入框中，并同步到 PC 的光标处（默认开启自动粘贴；若关闭则手动 Ctrl+V）。整个过程 <3 秒。

#### 场景 2：代码注释 / 文档编写（画像 A）

> 陈先生在 VS Code 里写 Rust 代码，需要写一段较长的函数注释。他在手机上用讯飞输入法语音说出一大段中文注释，松手后文字自动粘贴到 VS Code 的光标处，稍作格式调整即可。比手打快 5 倍。

#### 场景 3：腾讯文档 / 飞书协作用（画像 B）

> 李女士在 Mac 上用浏览器打开腾讯文档写周报，打字打到手酸。她打开手机 BeeType，用微信输入法的语音功能说完周报内容，文字自动粘贴进文档光标处（macOS 下自动发送 Cmd+V）。比发到微信文件传输助手再复制快得多。

#### 场景 4：多语言混合输入（画像 B）

> 王先生在做中英混排的 PPT，手机输入法支持中英文混说。他用语音说"在 React 18 中使用 Suspense 实现流式 SSR"，识别结果自动粘贴到 PowerPoint 光标处。输入法的混排能力比 PC 端语音输入更准。

### 3.3 非目标场景（明确排除）

| 场景 | 排除原因 |
|---|---|
| 会议实时转写 | 本品是"按住说话→松手发送"的节奏，不支持持续流式转写 |
| 离线语音识别 | 复用输入法，依赖输入法自身的联网识别能力 |
| 跨网络（手机用 4G，PC 在公司） | 本品纯局域网，不做云端中继 |
| 多人同时输入一个 PC | 单席位模型：同时只服务一部手机（另一部可接管，但不能并行） |
| 自动粘贴到光标位置（无把握的环境） | Wayland 等禁止后台注入的环境不提供该能力，回退手动 Ctrl+V；其余平台默认自动粘贴 |

### FR-1：QR 码配对

**描述**：PC 端主窗口展示包含连接信息的二维码，手机端扫描后建立会话；会话身份分「绑定常用设备」与「临时接入」两种（见 FR-11）。

**入口**：PC 端主窗口（启动即可见，托盘「打开主窗口」/托盘图标左键亦可唤起）
**输出**：手机扫码后建立会话；若本次绑定常用设备，双方落盘长期凭证

**QR 码内容**：`beetype://<ip>:<port>?code=<配对码>`

**配对握手流程**：
1. 手机扫描 QR 码，解析出 `ip`、`port`、`code`
2. 手机向 `ip:port` 发起 TCP 连接（超时 5 秒）
3. 发送 `hello`：`{"type":"hello","code":"<64 hex>","client_id":"<手机 uuid>","device_name":"Xiaomi 14","hardware_id":"<android_id>"}`
4. PC 端校验配对码 → 席位空闲则按 [FR-11](#fr-11常用设备绑定与免配重连) 判定身份，回 `hello_ack`（含 `session`、PC 设备名、`capabilities`；仅新建常用设备时含 `token`）
5. 配对码立即换新（一次性）；PC 窗口先渲染「已连接」，0.9 秒后自动隐藏到托盘
6. 手机端显示电脑名；绑定了常用设备则同时落盘凭证并刷新「最近使用」时间

**配对码规则**：
- 32 字节 `/dev/urandom` 随机串（64 位 hex），**只随二维码下发，协议与 UI 都没有手输入口**
- 不存明文：PC 端只存 `SHA-256(code)`
- 每次 PC 启动重新生成；窗口展示期间若已过期或剩余不足 2 分钟，轮询时自动换新（未连接时才换）
- 配对成功后立即换新，杜绝重放

**边界约束**：
- 有效期 5 分钟；过期后扫码得到 `bad_code`，手机提示「二维码已失效，请扫描电脑窗口上的最新二维码」
- 同一时间只服务一部手机（单席位，见 FR-13）；席位被占时扫码得到 `occupied`
- 鉴权失败（码错 / token 不匹配 / 缺凭证）同 IP 累计 5 次后冷却 60 秒

### FR-2：设备连接管理

**描述**：会话建立后手机端维护与 PC 的 TCP 长连接，非用户意图的断线按退避自动重连。

**怎么知道"断了"**（两条互补的路径）：

1. **对端关闭连接**（收到 FIN/RST）：电脑上退出程序、点「重启应用」、进程被杀、电脑端主动踢人——操作系统在握手层就会把连接关掉，手机立刻知道。**不需要任何协议消息**。
2. **判活超时**：对端只是断网（电脑关 Wi-Fi、拔网线、路由器重启、AP 隔离）时，TCP **不会报错**，连接在手机上看起来完全正常。因此手机每 5 秒发一次心跳，**15 秒内没收到任何服务端回应就判定连接已死**并开始重连。判定只在前台做，且切回前台会重置计时基准——否则后台/Doze 期间定时器被系统延迟，醒来会把健康连接误判成已死。

**输入**：已绑定电脑凭证（ip + port + token）
**输出**：稳定的 TCP 长连接，双向心跳保活

**连接生命周期**：

| 状态 | 触发条件 | 行为 |
|---|---|---|
| 已绑定未连接 | APP 冷启动 / 用户点「重新连接」 | 缓存 IP 直连（2.5 秒超时）与 UDP 发现并行，总预算约 3 秒 |
| 连接中 | TCP 已建立，等待 hello_ack | `hello` 超时 5 秒 |
| 已连接（持席） | 握手成功 | 每 5 秒 ping 保活，可发送文本 |
| 占用 | 已认证常用设备，但席位被临时方占着 | 连接保持，显示「电脑使用中」+ 接管按钮（FR-13） |
| 重连中 | 非用户意图的断线 | 快速退避重试约 1 分钟（1/2/4/8/10/10/10/10/10 秒）；试满即停手，显示「已停止重试」+「重新连接」 |
| 停止重连 | 用户手动断开 / PC 端主动断开 / 凭证被拒 | 本进程内不再自动重连 |

**心跳机制**：
- 手机每 5 秒发 `ping`，PC 回 `pong`
- PC 端 15 秒没收到任何消息即判定断线并释放席位（3 个心跳周期，容 Doze 延迟）
- 手机端没有 pong 超时：断线由 socket 关闭事件感知，另有 TCP keepalive（10s 空闲 + 5s × 3 次探测）兜底

**断线处理**：
- 手机端断线：按上述退避重连，期间显示「连接失败，重试中…」；试满一轮后停止重试，切回前台、网络变化、点「重新连接」都会重新开始一轮
- PC 端断开：托盘状态行回到「⚪ 等待配对」，席位释放，等待手机重连
- 手动断开（点「断开」）与 PC 主动断开（`owner_disconnect`）都视为用户意图：本进程不再自动重连，冷启动或点「重新连接」才恢复
- 凭证被拒（`unauthorized`，典型为 PC 端已解绑）：手机删除本地凭证并停止重连

### FR-3：语音文字接收与发送

**描述**：手机端提供一个输入框，用户用已装输入法的语音功能说话，APP 检测到「松手提交」后把全文通过 TCP 发给 PC。

**输入**：输入法语音识别结果（`InputConnection.commitText()` 或直接键入）
**输出**：文本经 TCP 送达 PC，PC 回 `ack`

**触发规则（关键设计）**：
- 语音输入：判据是 composing 的**下降沿**——按住说话期间 composing 持续有效（换气停顿也不断），松手提交时 composing 变 OFF，此刻立即发送（0ms 延时）
- 普通键盘输入：300ms 防抖，静止后发送当前全文
- 发送成功即清空输入框；失败保留全文并提示，输入卡右下角有兜底发送按钮

**交互流程**：
1. 用户打开 APP → 自动连接 PC → 输入框获焦、软键盘唤起（冷启动竞态时以 350ms 间隔最多重试 3 次）
2. 按住输入法麦克风说话 → 松手 → 输入法提交文本
3. APP 打包 `{"type":"text","id":"<id>","text":"识别内容","ts":<毫秒>}` 并经 TCP 发送
4. PC 回 `ack`：`{"type":"ack","id":"<id>","ok":true,"pasted":true,"srv_recv_ms":<毫秒>}`
5. 收到 `ok:true` 清空输入框；`ok:false` 保留内容并提示失败原因

**边界约束**：
- 单行协议上限 256KB；PC 端收到超长行直接断开连接（不截断、不做长度提示），实际使用远达不到
- 编码 UTF-8，支持中英混排与 emoji
- `ack` 超时 5 秒，超时按失败处理（内容保留可重试）
- 空文本（`trim()` 后为空）不发请求
- 未持席时输入框禁用，不发请求
- 输入法适配矩阵见 NFR-19（微信输入法已验证；搜狗等「逐句提交」类不适用）

### FR-4：剪贴板写入

**描述**：PC 端收到文本后写入系统剪贴板（覆盖当前内容），随后按设置自动粘贴 / 自动发送。

**输入**：`{"type":"text","id":"...","text":"..."}`
**输出**：剪贴板内容被替换为新文本；回 `ack`

**写入链（按序执行）**：
1. 非席位持有者 / 未认证 / 等待接管中的连接发来的 text → 回 `ack{ok:false, code:"not_connected"}`，不动剪贴板
2. 文本为空 → 回 `ack{ok:false, code:"empty_text"}`，不动剪贴板
3. 写入剪贴板（Tauri clipboard-manager → arboard）
4. 写入失败 → 弹系统通知「剪贴板写入失败，请重试」，回 `ack{ok:false, code:"clipboard_error"}`
5. 自动粘贴：开关生效 + 会话支持按键注入 + BeeType 自己的窗口没有焦点 → 模拟快捷键粘贴（见 FR-10）
6. 自动发送：粘贴成功后若开启则模拟 Enter
7. 回 `ack{ok:true, pasted:<是否真的粘贴了>, srv_recv_ms:...}`

**策略与边界**：
- 覆盖式写入，**不备份、不还原**旧剪贴板内容
- **不检测剪贴板内容类型**：图片/文件类内容会被直接覆盖（v0.1 设想的「非文本保护」未实现，理由见 [SECURITY.md](../SECURITY.md) 的已知边界）
- 自动粘贴失败时静默降级为「仅写入剪贴板」，文字仍在剪贴板里，用户可手动 Ctrl+V
- 成功不弹通知（避免打扰），只有写入失败才发系统通知

**描述**：PC 端常驻托盘；全部管理操作集中在主窗口，托盘只保留状态查看、开窗、踢人与退出。

**托盘菜单**：

```
┌─────────────────────────┐
```

**主窗口**（380×520，可缩放，最小 340×120）：

- 窗口高度在启动时量一次真实内容高度后固定，之后不随状态变化 resize

**配对码展示**：即主窗口主页的二维码卡（没有独立弹窗）；窗口展示期间配对码自动续期，不会变成死码

### FR-7：身份与凭证持久化

**描述**：两端各自持久化本机身份与对端凭证，重启后自动恢复关系；临时关系不落盘。

**PC 端存储**：`~/.config/beetype/config.json`（macOS / Windows 为对应平台配置目录），文件 0600、目录 0700，原子写入

```json
{
  "port": 8765,
  "autostart": false,
  "auto_paste": true,
  "auto_send": false,
  "code_hash": "<SHA-256(配对码)>",
  "code_expires_at": 1730000300000,
  "device_id": "<本机 uuid>",
  "device_name": "hejiong-PC",
  "primary": {
    "client_id": "<手机 uuid>",
    "name": "Xiaomi 14",
    "token_hash": "<SHA-256(token)>",
    "hardware_id": "<android_id>",
    "last_ip": "192.168.31.50",
    "paired_at": 1730000000000,
    "last_seen": 1730000000000
  }
}
```

**手机端存储**：SharedPreferences
- `client_id`：本机 UUIDv4
- `device_name`：手机展示名（启动与切回前台时同步系统真实设备名）
- `output_devices`：已绑定电脑数组 `[{device_id, name, device_type, ip, port, token, capabilities, last_connected_ms}]`
- 旧版键（`pc_ip`/`pc_port`/`pairing_code`/`is_paired`）初始化时清除一次——旧配对码无法兑换新 token，必须重新绑定

**恢复逻辑**：
1. PC 端启动 → 读配置 → 生成新配对码；常用设备记录存在则随时接受该常用设备的 token 重连
2. 手机端启动 → 有已绑定电脑则自动连接（缓存 IP 直连 + UDP 发现并行，见 FR-12）
3. 临时会话（未建立绑定关系）两端都不写任何持久化数据，断开即忘

> 发送成功不弹提示（输入框清空本身就是反馈），只有失败才提示。

### FR-10：自动粘贴 / 粘贴后自动发送

**描述**：PC 端写剪贴板后自动模拟粘贴（可选再回车），用户零手动。

**实现方式**：Rust 的 enigo 库直接做按键注入——Linux 走 X11 XTest、Windows 走 SendInput、macOS 走 CGEvent。**不调用 xdotool / osascript / PowerShell 等外部命令**，用户无需额外安装。

**行为**：
- 自动粘贴默认**开启**（设置页可关）；自动发送默认关闭，且依赖自动粘贴（关闭自动粘贴会联动关闭自动发送）
- **写入后读回校验**：读到的是别的内容（剪贴板被其他进程抢走，典型是有剪贴板管理器的机器）就重写一次；写入报错或重写后仍不一致 → 按写入失败处理（提示 + `ack ok:false`）；读不回来则按原样继续（不因为"校验不了"把能用的粘贴挡掉）
- 快捷键：Linux 终端窗口 `Ctrl+Shift+V`（按 `WM_CLASS` 识别终端，识别失败安全回退 `Ctrl+V`）、macOS `Cmd+V`、其余 `Ctrl+V`
- **按序注入**：粘贴快捷键与回车复用同一条注入连接，顺序不依赖墙钟时间
- **回车前复核焦点**：注入前记下焦点窗口，发回车前再查一次；窗口变了就**不发回车**（文字已粘贴，用户自己按回车即可），只记日志、不在手机端打扰用户
- **回车余量是安全余量，不是性能参数**：基准 250ms + 每 200 字符 1ms（上限 +500ms）。目标应用可能是异步插入（Chromium/Electron 系），快了没有收益、漏了就是消息没出去；因此取值刻意宽松，**不按机器、不按应用做特调**
- BeeType 自己的窗口处于焦点时**跳过**粘贴，避免文字糊进配对窗口
- 粘贴失败静默降级为「仅剪贴板」，文字不丢
- Linux Wayland 会话判定为不支持（回退纯剪贴板手动 Ctrl+V），设置页显示「当前桌面会话不支持全局按键模拟」

> 时序设计、已经规避掉的竞态（X11 所有权传播）与仍然存在的边界见 [TECH_DESIGN.md](./TECH_DESIGN.md#10-粘贴时序与残余竞态)。

### 4.2 持久配对模型（FR-11 ~ FR-14）

> 这一节描述首个里程碑之后落地的身份/信任模型：一台电脑长期只记住一部「常用设备」，其余手机一律临时；临时关系两端都不落盘。它是 FR-1/FR-2/FR-7 的行为依据。

#### FR-11：常用设备绑定与免配重连

**描述**：PC 端长期记住一部常用设备，该手机此后打开 APP 即免码直连。

**绑定**：
- 唯一入口是 **PC 窗口的「记住这台手机」勾选框**，仅还没有常用设备时出现，**默认不勾**（扫码默认就是临时设备）
- 勾选后对**下一次**码配对生效；绑定成功时 PC 生成 32 字节随机 token，明文随 `hello_ack` 下发**一次**，两端都只落盘 `SHA-256(token)`
- 一旦已有常用设备，勾选框消失，此后任何扫码接入都是临时身份

**免配重连**：手机持 token 发 `hello{token, client_id}` → PC 比对 `token_hash` 命中即接入常用设备席位（PC 重启、配对码换新都不影响）。

**重装恢复**：手机 APP 重装后 `client_id` 会变，但 `hardware_id`（Android ANDROID_ID / iOS Keychain UUID）不变；扫码时若任一命中常用设备记录，直接恢复常用设备身份且**不下发新 token**。

**临时身份**：未勾选，或常用设备席位已被占 → `session = "transient"`，PC 不存凭证、手机不落盘，断开即忘。

#### FR-12：受限设备发现（电脑换 IP 无感）

**描述**：手机自动连接时，除直连缓存 IP 外并行走一次 UDP 发现，用于在电脑 IP 变化后仍能找到它。

**协议**：
- 手机广播（3 轮，间隔 300ms，总预算约 1.1 秒）：`{"type":"vl_disc_req","protocol":1,"client_id":"<手机 uuid>","proof":"<SHA-256(token)>"}`
- PC 端**仅在与常用设备记录完全匹配时**单播应答 `vl_disc_resp{device_id, device_name, device_type, port, busy, capabilities}`
- 无常用设备、`client_id` 不符、`proof` 错误 → **一律静默**（电脑对陌生设备隐身，不产生任何应答）

**行为**：
- 直连缓存 IP 成功 → 走最快路径（约 100~300ms），发现结果直接丢弃
- 直连网络层失败 → 用发现的来源 IP 补连一次并刷新缓存（DHCP 换 IP 的主路径）
- `busy: true` 时手机可直接渲染「电脑使用中」页，省一次 TCP 尝试
- 临时手机没有 token，发不出有效 proof，发现功能对其实质不存在

#### FR-13：单席位仲裁与常用设备接管

**描述**：一台电脑同一时刻只服务一部手机（光标只有一个）。

**仲裁规则**（收到 `hello` 时按身份分流）：

| 情况 | 处理 |
|---|---|
| 席位空闲 | 直接接入 |
| 常用设备 token + 席位被**同一 client_id** 的旧连接占着 | 踢旧接新（旧连接收到 `session_ended{replaced}`） |
| 常用设备 token + 席位被临时方占着 | 回 `hello_ack{status:"occupied"}`，**连接保持**（等待接管），手机在打字区提示可点「连接」接管；临时凭证撞占用则清记录回扫码页 |
| 码配对 + 席位被占 | 回 `occupied`，不认证、不绑定、不换码 |

**接管**：用户在手机上点「连接」→ 发 `takeover` → PC 踢掉当前持有者（对方收到 `session_ended{owner_takeover}`，轻提示「这台电脑的主人已连接」）并把席位交给常用设备 → 回 `takeover_ack{ok:true}`。**临时方发起的 takeover 一律被拒**（协议层不存在手机端篡位路径）。界面上的按钮仍叫「连接」——接管只是它的一个语义，不额外造词。

**席位释放**：
- 主动断开（点「断开」发 `bye` / 杀 APP 导致 TCP 关闭）→ PC 立即释放席位
- 异常（崩溃 / 断网 / 被系统杀后台）→ PC 端 15 秒心跳超时收尸
- 切后台不主动断开：心跳与连接保持，切回零等待

#### FR-14：解绑与在线降级

**描述**：解除常用设备关系（换机场景）。

**入口**：PC 设置页「常用设备」区域的「解除绑定」（设置页对低频/危险操作有明确的分区与样式）

**行为**：
- 清空 `primary` 记录 → 旧 token 立即失效（再用即 `unauthorized`）
- 若常用设备**正在线**：不踢人，而是把当前会话降级为临时继续服务（发 `session_downgraded`，手机删本地凭证、界面标记「临时设备」）；解绑是用户在 PC 上的主动操作，打断正在进行的输入没有收益
- 手机端此后无凭证，下次打开不再自动连接；要再连需重新扫码（若被勾选「记住」则重新绑定为常用设备）

#### FR-15：临时设备的断线续连

**描述**：临时设备（未绑定常用设备）的手机被系统杀进程后，在一个**短窗口**内重开 APP 可免扫码自动连回，体验与常用设备连接一致；窗口过期则需重新扫码。

**为什么要有它**：临时设备此前"断了就是断了"——手机既不记 IP 也不记凭证，回到 APP 只能重新扫码，而扫码需要走到电脑前把二维码调出来。临时设备的典型场景是"别人临时用我的电脑"或"公共电脑"，同样会遇到 Android 杀后台。

**窗口与设置**：
- 窗口为**滑动**语义：配对成功、心跳、发文字、续连成功都把到期时间往后再推一个窗口长度——**人在用就一直有效，停手超过窗口才失效**；它不影响会话本身能持续多久（连接不断就一直能用）。
- PC 设置页「临时设备断线后自动续连」提供四档：**关闭 / 5 分钟（默认）/ 30 分钟 / 2 小时**。默认取最短，是因为临时设备不是核心场景（核心是"私人手机连自己的电脑、一直连着"），临时主要用于访客与公共机；30 分钟/2 小时留给确实需要更宽松的场合。
- 窗口时长由 PC 决定并在握手响应中告知手机（PC 是权威方）。

**身份与安全**：
- **所有临时身份的会话都有续连凭证**：码配对的临时设备，以及"常用设备被解绑后降级来的临时设备"（后者在 `session_downgraded` 里补发）；常用设备走原有 token，不受影响。
- **电脑换了 IP 也能续连**：临时设备只记得 IP+端口，直连不上时改用局域网广播找一次；电脑认得"窗口期内仍有效的临时续连凭证"就应答，手机据此用新 IP 连回。这也意味着发现服务从"只对常用设备现身"放宽到"也对窗口期内的临时访客现身"（安全代价见 SECURITY.md）。**换到别的网络（连了另一个 Wi-Fi、用移动数据）仍然回不来**——那属于环境不通，不是凭证问题。
- PC 端**不落盘**：只在内存里存续连凭证的 SHA-256 + client_id + 到期时刻，且只保留最近一条（不积累访客凭证）；进程退出即消失。
- 手机端会落一条独立的短期记录（`transient_session`），与「我的电脑」列表分开；窗口过期或凭证被作废时立即清除。
- **立即失效路径**：TTL 到期 / 主人在托盘点「断开当前手机」/ 手机端点「断开」/ **PC 端服务退出或重启**。席位被占时按既有规则处理（临时方没有接管入口）。
- **为什么 PC 重启也算失效**（一条刻意的边界，别顺手"优化"掉）：临时续连记录只存在 PC **内存**里。这条边界表达的是一条原则——**发送方（临时连接的手机）自身出问题，给它机会**（手机被系统杀后台、重开 APP，PC 还正常运行着，窗口期内自动连回）；**接收方（PC 服务）自身出问题，不给机会**（PC 退出/重启/点「重启应用」装新版，记录随进程消失，临时方必须重新扫码）。否则它就不叫"临时接入"了。绑定手机不受影响：它有长期凭证，PC 重启后照旧自动连回。
- **谁出问题，谁负责**（临时接入的断开处置表）：

  | 判定信号 | 谁来负责 | 手机端行为 |
  |---|---|---|
  | 收到"对端关闭连接"（FIN）——电脑上的程序退出/重启/被踢。**两道护栏**：关闭时手机自己还在正常通信（不是被系统挂起、静默到被 PC 心跳超时收尸）；且手机网络没有刚刚变化过（不是自己换网络导致的连接结束） | **接收方（PC）** | **立刻**清掉续连记录、回扫码引导页，提示「连接已失效，请重新扫码」（不干等窗口期） |
  | 判活超时（静默断）+ 手机自己的网络没变，且一轮高频重试（约 1 分钟）试满仍连不上 | **接收方（PC）** | 同上：清记录、回扫码页、同一句提示 |
  | 手机自己的网络变了（换 Wi-Fi / 只有移动数据），或还在高频重试中 | **发送方（手机）** | **保留记录、给机会**：窗口期内回到 APP、网络恢复、或点「连接」都能自己连回 |

  - 静默断开为什么不立刻丢记录：电脑网络变了、路由器抖了一下、电脑睡了几秒，在手机上**看起来完全一样**，所以先给一轮高频重试的机会，试满再看方向。
  - 手机侧换网络后仍连不上时，界面停在设备页并提示「请确认手机和电脑连着同一个 Wi-Fi」——换回同一网络后能自己连回，不该把记录丢掉。
  - **续连记录到期时界面自动刷新**回扫码引导页（手机端界面是事件驱动的，到期那一下要主动刷新，否则会停在"未连接"的输入卡上直到用户碰它）。
  - **本地到期时间随心跳同步**：手机本地记的到期时间只在"配对/续连成功"时刷新，而 PC 的窗口是每次心跳都在往后滑的——所以心跳回包会带上窗口剩余时长，手机收到就刷新本地值（节流 30 秒一次）。不同步的话，连接正常用了超过窗口时长之后，手机会在窗口还没到时自以为过期，一断网就把还能用的记录丢掉（用户实测：锁屏回来只能重新扫码）。
  - **锁屏/切后台不算"电脑侧问题"**：那时系统挂起本进程定时器，我们没发心跳，PC 端 15 秒心跳超时才会关掉连接——这条 FIN 的责任在手机侧，记录要保留，窗口期内回到 APP 仍能续连。
- **重连的触发方式**（高频重试停下来之后）：
  - **自动**：切出 APP 再切回（回到前台即重试一轮）、网络变化（换 Wi-Fi / 切回原网络 / 开关移动数据）；
  - **手动**：点胶囊上的「连接」；
  - **被他人占用**：点「连接」会先被告知"另一台手机正在使用这台电脑"并按提示再点一次即可接管（见 §6.7）。
- 被电脑拒绝凭证时，手机端**按凭证类型说不同的话**：绑定手机 →「电脑已解除与你的绑定，请重新扫码」；临时接入 →「连接已失效，请重新扫码」（同时覆盖"PC 重启忘了它"与"窗口过期"，不谎称被解绑）。
- 过期后的手机端表现：清理记录、回到扫码引导页，并提示「临时会话已过期，请重新扫码」。
- **手机上主动点「断开」会同时作废本地续连记录**（这次会话到此为止），界面回到扫码引导页；若不断开，记录留到窗口过期为止。
- **身份标签会自动对齐**：电脑每次心跳（约 5 秒）都回报一次权威身份，手机发现不一致立刻纠正——即使某次"被降级/被设为常用"的推送丢了，标签也会在一个心跳周期内自己变对。
- 临时设备依然拿不到常用设备 token，也无法解绑或篡位。

#### FR-16：把当前手机绑定为常用手机

**描述**：在电脑还没绑定手机时，可以把**当前在线的这台手机**一键绑定为常用手机，不必让它重新扫码。

**入口**：PC 设置 →「手机绑定」卡片。仅当「还没绑定手机 + 当前有临时接入」时才出现「绑定这台手机」按钮，并显示该手机名称。

**行为**：
- PC 生成长期 token 并写入常用设备记录（含 client_id、名称、硬件指纹 hardware_id、来源 IP），随后把 token 推送给手机；
- 手机收到后按与扫码绑定完全相同的逻辑落盘为常用电脑，并撤掉临时续连记录；界面标签由「临时设备」变为常用；
- **推送失败会回滚绑定**（不留"PC 以为绑了、手机没凭据"的不一致状态），并在界面上提示原因；
- 席位身份当场升级为常用设备，托盘状态同步（通知当场发出，不等下一次心跳）。

**边界**：
- 已完成绑定（已有常用设备）时不显示该按钮；错误路径由 PC 原样返回提示（如「已经绑定了常用设备，请先解除绑定」）；
- 设为常用后手机持有的是**长期凭证**（这才是常用设备语义），与临时设备的短期续连凭证是两回事。
- **临时接入撞上「被占用」时不给任何提示**：那属于正常的连接竞争——清掉临时记录回扫码引导页即可（电脑此刻也不显示二维码，用户一看就知道它正忙）。接管只对绑定手机开放（PC 端也只放行这种连接）。

#### FR-17：一键重启应用

**描述**：PC 托盘右键菜单提供「重启应用」，用于装好新版本后一键切换，不必手动退出再从菜单打开。

**行为与约束**：
- 重启会**延迟 1 秒启动新进程再退出当前进程**（单实例机制下，新旧进程重叠会让新进程自杀，见 TECH_DESIGN §2.8）；启动失败则留在当前界面并提示，不会"点一下应用就没了"；
- 可执行文件路径在**启动时**捕获，因此"先安装新版本、再点重启"会切换到新装的二进制；
- 会短暂断开手机连接：常用设备会自动重连；临时设备若在续连窗口内也会自动回来，否则需重新扫码（按钮副文案已说明）。

| NFR-19 | 输入法兼容 | 以"按住说话期间 composing 持续有效、只有松手才提交"为适配判据。微信输入法已真机验证（含带停顿长句）；豆包、讯飞、Gboard 待 Spike。已知不适配/受限：搜狗（句末停顿 422ms 起即逐句提交，停顿与松手不可区分）；百度输入法（长语音开关已开，短停顿 composing 不断，但持续听写 15~26 秒会被引擎自动分段提交，触发条件不可预测，且分段发送会使 PC 剪贴板只保留最后一段——定性为"单句可用、长文 dictation 不保证"）。适配策略：维持 composing 下降沿 0ms 即发，不为自动分段类输入法加全局观察窗（会令所有输入法丧失"松手即发"）；长文场景建议使用微信输入法 |

| NFR-21 | 网络环境 | 同一局域网（同一子网），支持 WiFi 和有线网络，不要求公网；发现功能需要广播可达（AP 隔离/访客网络下会退化为仅直连缓存 IP） |

### 6.3 断线重连流程

```
 手机端                                         PC 端
   │                                            │
   │  检测到 socket 关闭（WiFi 抖动/PC 重启）     │  15s 无消息则收尸、释放席位
   │  → 状态「连接失败，重试中…」                   │  → 托盘「⚪ 等待配对」
   │                                            │
   │  第 1 次重试（1s 后）→ 失败                  │
   │  第 2 次重试（2s 后）→ 失败                  │
   │  第 3 次重试（4s 后）→ TCP 连上              │
   │  → hello{token}                            │
   │                              ←──────────   │  token 命中 → 接入常用设备席位
   │  → 状态「已连接」，键盘唤起                  │  → 托盘「🟢 手机名」
   │                                            │
   │  若电脑换了 IP：直连失败 → UDP 发现应答       │
   │  → 按应答来源 IP 补连并刷新缓存              │
   │                                重连成功 ✓
```

**重连策略**：
- **快速试一阵就停手**：1/2/4/8/10/10/10/10/10 秒（约 1 分钟，共 10 次），试满即停止自动重试，胶囊显示「已停止重试」+「重新连接」。
  - 为什么不做慢速长期重试：等到能连上时，慢速重试并不"及时"，用户不如当场点一下；而长期定时器在移动数据上会反复把无线电拉回高功耗，白耗电。
  - **什么时候重新开始**（都表示"用户回来了 / 环境变了"）：切回前台、网络变化（换 Wi-Fi、切回原网络、开关移动数据）、点「重新连接」、重新扫码。
  - **只有移动数据时根本不重试、不广播**：本产品只在同一局域网下能工作，连上去也无从谈起；此时打字区提示「请确认手机和电脑连着同一个 Wi-Fi」，Wi-Fi 一回来由网络变化监听自动拉起。
- 用户手动断开、或被 PC 主动断开（`owner_disconnect`）后停止自动重连，需点「重新连接」或冷启动
- 凭证被拒（PC 端已解绑）→ 删除本地凭证并停止重连
- 切回前台立即补试一次（后台 Doze 会延迟定时器）

### 6.4 发送失败处理流程

```
 手机端
   │
   │  发出 text 后 5 秒内未收到 ack
   │  → 输入框内容保留（不清空）
   │  → 底部提示「发送失败（原因），文字已保留，点右侧按钮重试」
   │  → 输入卡右下角出现发送按钮（兜底重发）
   │
   │  用户点击发送按钮
   │  → 重新发送（新 id）
   │  → 收到 ok:true → 清空输入框
   │  → 再次失败 → 内容仍保留，可继续编辑或重试
   │
   │  收到 ok:false 时按 code 提示：
   │  · not_connected    → 连接已不在席位（被接管 / 被顶替）
   │  · empty_text       → 内容为空，未发送
   │  · clipboard_error  → PC 剪贴板写入失败（PC 端同时弹系统通知）
```

### 6.5 剪贴板处理流程

```
 PC 端
   │
   │  收到 text 消息
   │  → 检查是否持席（未持席 → ack{ok:false, code:"not_connected"}）
   │  → 检查文本非空（空 → ack{ok:false, code:"empty_text"}，不动剪贴板）
   │
   ├─ 写入成功（覆盖剪贴板当前内容）
   │   → 读回校验：读到别的内容（被其他进程抢走）→ 重写一次再验
   │   → 自动粘贴条件满足时：先记下焦点窗口 → 模拟粘贴
   │   → 自动发送开启且焦点窗口未变 → 等 250ms+（长文本递增）后发 Enter
   │   → 焦点窗口变了 → 不发回车（只记日志，手机端不提示）
   │   → ack{ok:true, pasted:<bool>, srv_recv_ms}
   │
   └─ 写入失败
       → 系统通知「剪贴板写入失败，请重试」
       → ack{ok:false, code:"clipboard_error"}

 说明：不备份旧剪贴板内容，也不检测内容类型——图片/文件类内容会被直接覆盖
 （v0.1 设想的「非文本保护」未实现，见 SECURITY.md 已知边界）。
```

### 6.6 PC 端托盘与窗口交互

| 用户操作 | 触发结果 |
|---|---|
| 左键单击托盘图标 | 打开并聚焦主窗口，落到**主页** |
| 托盘「打开主窗口」 | 打开并聚焦主窗口，落到**主页** |
| 托盘「设置」 | 打开窗口并**直接切到设置页** |
| 托盘「重启应用」 | 延迟 1 秒启动新进程后退出当前进程（失败则系统通知提示） |
| 托盘状态行（⚪/🟢） | 仅展示，点击无动作 |
| 托盘「断开当前手机」 | 结束当前会话：手机收到 `session_ended`，席位立即释放 |

### 6.7 手机端界面状态机

**界面只有三种信息**：状态点（绿=已连接 / 灰=未连接，呼吸=正在尝试）+ 电脑名 + 一个动作按钮（连接 / 断开）。胶囊里**没有身份词、没有原因、没有过程**。

| 当前状态 | 事件 | 下一状态 |
|---|---|---|
| 启动（有绑定电脑） | 自动连接 | 连接中（点呼吸、词「连接中」、无按钮） |
| 启动（无绑定电脑） | — | 扫码引导页（胶囊：灰点 +「未连接电脑」，无按钮） |
| 连接中 | `hello_ack ok` | 已连接（绿点常亮，按钮「断开」） |
| 连接中 | `hello_ack occupied` + 本机是绑定手机 | 被占用：**立即停止自动重连**，打字区提示「另一台手机正在使用这台电脑；点「连接」即可立即接管」，按钮「连接」（点它即接管） |
| 连接中 | `hello_ack occupied` + 本机是临时接入 | 清掉临时记录，回扫码引导页（电脑此刻也不显示二维码，用户一看就知道正忙） |
| 连接中 | 网络失败 / 凭证被拒 / 被限流 | 未连接（灰点，按钮「连接」；凭证被拒才删本地凭证，被限流只等一会儿） |
| 已连接 | 用户点「断开」 | 未连接（灰点，按钮「连接」，不再自动重连） |
| 已连接 | 非用户意图的断线 / 判活超时 | 连接中（快速退避重试约 1 分钟后停手，变灰点 + 按钮「连接」） |
| 已连接 | `session_ended{owner_takeover}` | 未连接 + 轻提示「这台电脑的主人已连接」 |
| 已连接 | `session_downgraded` | 已连接（身份变为临时接入，界面不标注；窗口过期时才提示） |
| 已连接 | 输入变化 / 语音松手 | 发送中 →（ack ok）已连接 /（ack 失败或超时）内容保留 + 提示 |
| 扫码引导页 | 扫码成功 | 已连接 |

**点色与呼吸**：绿常亮 = 已连接；灰常亮 = 未连接（含被占用、主动断开）；柔和呼吸（透明度 0.35↔1.0、约 1.2 秒一个来回）= 正在尝试（含重试中）。系统开启"减少动态效果"时，呼吸退化为灰常亮。

**打字区**（输入框里那行灰字）只讲"该做什么"：默认「连接成功后即可语音输入文字」；能判断不在同一局域网时换成「请确认手机和电脑连着同一个 Wi-Fi」；被占用且本机是绑定手机时换成接管提示。

## 7. 技术方案

### 7.1 整体架构

```
┌──────────────────────────────┐                 ┌──────────────────────────────┐
│        手机端（Flutter）      │                 │      PC 端（Tauri + Rust）    │
│                              │                 │                              │
│  UI 层                       │   TCP + JSON    │  server.rs    认证/席位/剪贴板│
│   home_page / scan_page      │ ←─────────────→ │  protocol.rs  消息编解码      │
│  逻辑层                      │   行协议        │  paste.rs     按键模拟        │

│   storage / discovery        │   UDP 发现      │  config.rs    身份与凭证      │
│  平台通道 beetype/device      │ ←─────────────→ │  lib.rs       托盘/窗口/命令  │

```

两端各自持久化：手机存 `client_id` + 已绑定电脑列表（含 token）；PC 存 `device_id` / `device_name` + 唯一常用设备记录（含 `token_hash`）。临时关系两端都不落盘。

模块细节、协议字段表与席位状态机见 [TECH_DESIGN.md](./TECH_DESIGN.md)。

#### 7.2.3 TCP Server 设计

```
ServerState（跨线程共享）
├── session: Mutex<Option<ActiveSession>>   # 唯一席位（单光标）
├── config: Mutex<Config>                   # 身份/凭证/开关
├── pairing_code: Mutex<String>             # 当前配对码明文（仅内存，用于渲染二维码）
├── auth_fails / auth_cooldowns             # 同 IP 5 次失败 → 冷却 60s
├── auto_paste / auto_send                  # 实际生效值（用户意愿 && 平台支持）
└── status_item / disconnect_item           # 托盘菜单项句柄

每个连接一个线程：handle_connection
├── 读超时 5s；已认证连接 15s 无消息收尸
├── handle_message：hello（认证）/ text（剪贴板 + 自动粘贴）/ ping / takeover / bye
└── 退出时仅当自己仍是席位持有者才释放席位（client_id + kick 指针双比对）

踢人：kick_session() 置标志 + shutdown(Read) 唤醒阻塞读，立刻发 session_ended 并退出
```

#### 7.2.4 剪贴板写入策略

```
fn handle_text(id, text):
    1. 非持席连接 → ack{ok:false, code:"not_connected"}（不动剪贴板）
    2. text.trim().is_empty() → ack{ok:false, code:"empty_text"}（不动剪贴板）
    3. clipboard.write_text(text)          # Tauri 插件 → arboard，覆盖式
       失败 → 系统通知 + ack{ok:false, code:"clipboard_error"}
    4. 自动粘贴：开关生效 && 平台支持 && BeeType 窗口未聚焦 → enigo 模拟快捷键
    5. 自动发送：粘贴成功后 && auto_send 生效 → 模拟 Enter
    6. ack{ok:true, pasted:<bool>, srv_recv_ms}
```

> 不检测剪贴板内容类型（无非文本保护），也不备份/还原旧内容。

**发送时机判定**（`_onValueChanged`）：


#### 7.3.4 TCP 连接管理

```dart
class TcpService {
  Socket? _socket;

  connect(ip, port, {timeout = 5s})        // TCP 层，认证前状态保持 connecting
  hello({code | token, clientId, deviceName, hardwareId}) → HelloOutcome
  takeover() → bool                        // occupied 时请求接管
  bye()                                    // 优雅断开（等 bye_ack 兜底 1.5s）
  sendText(text) → AckResult               // ack 超时 5s
  disconnect()                             // 硬断开
  // 心跳：每 5 秒 ping；无 pong 超时，断线由 socket 事件 + TCP keepalive 感知
}
```

上层 `TextSender` 负责编排：`autoConnect()`（缓存 IP 直连与 UDP 发现并行）、`pairWithCode()`、`userDisconnect()`（本进程内不再自动重连）、`downgradeToTemp()`、`forgetDevice()`。

### 7.4 通信协议设计

JSON 行协议：每条消息一行 UTF-8 JSON，以 `\n` 结尾，单行上限 256KB（PC 端收到超长行直接断开）。完整字段表见 [TECH_DESIGN.md](./TECH_DESIGN.md#3-通信协议)。

| 消息类型 | 方向 | 格式 |
|---|---|---|
| hello | 手机→PC | `{"type":"hello","code":"<64 hex>","client_id":"<uuid>","device_name":"Xiaomi 14","hardware_id":"<android_id>"}`（把 `code` 换成 `token` 即免配重连） |
| hello_ack | PC→手机 | `{"type":"hello_ack","ok":true,"status":"ok","session":"primary","device_id":"...","device_name":"hejiong-PC","device_type":"pc","token":"<仅新建常用设备时>","capabilities":{"auto_paste":true}}` |
| text | 手机→PC | `{"type":"text","id":"<id>","text":"内容","ts":1730000000000}` |
| ack | PC→手机 | `{"type":"ack","id":"<id>","ok":true,"pasted":true,"srv_recv_ms":1730000000123}` |
| ping / pong | 双向 | `{"type":"ping"}` / `{"type":"pong"}` |
| takeover / takeover_ack | 手机→PC→手机 | `{"type":"takeover"}` / `{"type":"takeover_ack","ok":true}` |
| bye / bye_ack | 手机→PC→手机 | `{"type":"bye"}` / `{"type":"bye_ack"}` |
| session_ended | PC→手机 | `{"type":"session_ended","reason":"owner_takeover" \| "owner_disconnect" \| "replaced"}` |
| session_downgraded | PC→手机 | `{"type":"session_downgraded"}` |

**约束与字段**：
- 编码 UTF-8，行分隔符 `\n`，单行 ≤256KB
- `id`：手机生成的消息 id，用于 text/ack 配对
- `ts`：毫秒时间戳；`srv_recv_ms`：PC 收到该消息的时刻（供端到端延迟统计）
- `ack.code` 取值：`not_connected` / `empty_text` / `clipboard_error`
- `hello_ack.status` 取值：`ok` / `occupied` / `bad_code` / `unauthorized` / `cooldown`
- 兼容性：`hello`/`hello_ack` 的新字段全部可选，旧客户端缺字段也能解析；非法 JSON 只记日志，不断连接

### 7.5 配对码与 token 安全设计

```
配对码（一次性）
  生成：PC 启动时 regenerate_code() → 32 字节 /dev/urandom → 64 位 hex
        → 存 SHA-256(code) 与 5 分钟过期时间
        → 明文只出现在二维码里（beetype://ip:port?code=...）
  续期：窗口轮询时若已过期或剩余 <2 分钟且当前未连接 → 自动换新
  校验：收到 hello{code} → 先查过期 → 再比对 SHA-256
        → 失败累计 5 次 → 该 IP 冷却 60 秒
  换新：配对成功立即换新，杜绝重放

token（长期凭证）
  签发：绑定常用设备时生成 32 字节 token，明文随 hello_ack 下发一次
  存储：PC 只存 SHA-256(token)；手机存明文（SharedPreferences）
  使用：手机 hello{token, client_id} → PC 比对 token_hash 命中即接入常用设备席位
        UDP 发现的 proof 也是 SHA-256(token)，抓到广播无法反推 token
  失效：PC 端解绑 → primary 清空，旧 token 立即失效（再用即 unauthorized）
```

| AC-45 | 关闭续连 | 设置里把该档位设为「关闭」，扫码临时接入后杀 APP 重开 | 不自动续连，直接回到扫码引导页 |
| AC-46 | 把当前手机绑定为常用手机 | 手机临时接入在线时，在 PC 设置 →「手机绑定」点「绑定这台手机」 | 杀 APP 重开自动连回；PC 端托盘与状态卡只显示手机名（不标注身份） |
| AC-47 | 转正的边界 | 已有常用设备时看「常用设备」卡片；以及在没有手机连接时尝试转正 | 已有常用设备时不显示转正按钮（只有解绑）；无连接时接口返回明确错误提示 |
| AC-48 | 一键重启 | 装好新版本后在托盘右键菜单点「重启应用」 | 窗口短暂消失后自动回来，版本号为新装版本，且常用设备自动重连；重启失败（如二进制被删）时留在界面并提示 |
| AC-49 | 每次唤起窗口都是重新进入 | 进设置页 → 往下滚几屏 → 点叉隐藏 → 托盘「打开主窗口」；再托盘「设置」→ 滚到下面 → 点叉 → 托盘「设置」 | 两次都落到对应页面，且**从顶部开始**（不残留上次的滚动位置）；托盘「打开主窗口」永远到主页，不会停在离开时的设置页 |
| AC-50 | 设置页不再显示已离线的手机 | 临时接入在线时进设置页停在「手机绑定」卡上，随后在手机上点「断开」 | 1 秒内卡片自行变成空态（不再显示那台手机与「绑定这台手机」按钮），无需重进设置页 |
| AC-51 | 提示不暴露实现细节 | 在「手机绑定」卡上点已失效的「绑定这台手机」 | 底部出现页内提示（如「设置失败：下发凭证失败，连接可能已断开」），4 秒后自行消失；**不出现系统弹窗**，文案里没有 URL/`Error:`/函数名一类实现细节 |
| AC-52 | 解绑即时生效 | 已绑定手机在线时在 PC 设置页点「解除绑定」 | 手机**立刻**（不等下一次心跳）按临时接入行事（断开后走窗口期续连、不再是长期免配重连），PC 设置页「手机绑定」卡立即变空态；连续「解绑 → 绑定这台手机 → 再解绑」多次，每一次手机都会跟着变 |
| AC-53 | 身份标签自愈 | 常用设备在线时在 PC 设置页解绑 | 即使那条推送因为任何原因没到，手机也会在一个心跳周期（约 5 秒）内把标签纠正为「临时设备」 |
| AC-54 | 限流不误删绑定 | 连续扫错码 5 次把电脑关进 60 秒冷却，随后打开手机 APP | 提示"连接失败，重试中…"并保留绑定与凭证；冷却过去后能正常连上，**不会**回到扫码页要求重扫 |
| AC-55 | 被解绑的明确提示 | 在 PC 上解除一台**离线**常用设备的绑定，随后打开手机 APP | 手机回到扫码引导页，并提示「电脑已解除与你的绑定，请重新扫码」（不再是静默跳页） |
| AC-56 | 连接失败的两类提示 | ① 手机改用移动数据（或连到另一个 Wi-Fi）后打开 APP；② 手机与电脑同一 Wi-Fi，但电脑关机 | ① 打字区提示「请确认手机和电脑连着同一个 Wi-Fi」；② **不出现任何 Wi-Fi 提示**，只有状态胶囊的「连接失败，重试中…」 |
| AC-57 | 临时设备换 IP 后自动连回 | 临时设备在线 → 杀掉手机 APP → 改掉 PC 的 IP（仍在同一局域网）→ 重开 APP | 窗口期内零操作自动连回，无需重新扫码 |
| AC-58 | 临时接入撞占用 | 电脑正被另一台手机使用时，用第三台（未绑定的）手机扫码 | 手机清掉临时记录、回到扫码引导页，**不给额外提示**（电脑此刻不显示二维码，本身就说明它正忙）；不会在占用者离开后偷偷连回去 |
| AC-59 | 只有移动数据时不重试 | 关掉手机 Wi-Fi（只留移动数据）后打开 APP，观察一分钟 | 一次尝试失败后即停手（不重试、不广播），胶囊显示「已停止重试」+「重新连接」，打字区提示「请确认手机和电脑连着同一个 Wi-Fi」；**打开 Wi-Fi 后自动重新连接**，无需手动操作 |
| AC-60 | 电脑连上手机热点也能连回 | 手机开热点 → 电脑改连该热点 → 手机上打开 APP（或在重试过程中） | 自动连上（广播打到热点网段 192.168.43.x），无需重新扫码 |
| AC-61 | 对端断网能及时感知 | 手机与电脑连着时，把**电脑的 Wi-Fi 关掉**（电脑上程序不退） | **8 秒内**（心跳 2 秒、判活窗口 6 秒）状态点从绿常亮变为呼吸、出现词「连接中」并开始快速重试（不再像以前那样一直绿灯、只有重开 APP 才连）；电脑网络恢复后自动连回或点「连接」即连上 |
| AC-62 | 电脑端退出程序 | 退出电脑端程序（正常退出 / 点「重启应用」/ 命令行 kill） | 状态点立刻变呼吸 + 出现「连接中」（连接被对端关闭，手机立即知道）；一轮快速重试后变灰点 + 按钮「连接」；电脑端重新打开后不点任何按钮也能自动连回 |
| AC-63 | 主动断开不显示任何状态词 | 在手机 APP 上点「断开」（或电脑端托盘断开） | 胶囊里**只有灰点 + 电脑名 + 按钮「连接」**，设备名后面没有任何词；点「连接」即重新连接 |

#### 8.1.1 持久配对模型验收（FR-11 ~ FR-14）

| 编号 | 验收项 | 验证方法 | 通过标准 |
|---|---|---|---|
| AC-31 | 绑定常用设备 | 扫码时勾选「记住这台手机」 | `hello_ack` 带回 token；PC config.json 出现 primary 记录且只有 `token_hash`；手机落盘该电脑 |
| AC-32 | 临时接入 | 已有常用设备时用第二台手机扫码 | `session=transient`，两端均无持久化写入，界面显示「临时设备」标签 |
| AC-33 | 占用与接管 | 临时手机在线时，已绑定手机打开 APP（或点「连接」） | 已绑定手机侧：打字区提示「另一台手机正在使用这台电脑；点「连接」即可立即接管」，且**自动重试立即停止**；点「连接」后临时方收到「这台电脑的主人已连接」并断开，已绑定手机接入 |
| AC-34 | 换 IP 无感 | 改变 PC 的 IP（DHCP 重分配）后打开手机 APP | 直连失败后按 UDP 发现应答的 IP 补连成功，并刷新缓存 IP |
| AC-35 | 发现隐身 | 用错误 proof / 随机 client_id / 未绑常用设备的 PC 发起发现请求 | 三种情况均无任何应答（抓包验证） |
| AC-36 | 解绑降级 | 常用设备在线时在 PC 设置页点「解除绑定」 | 连接不断开，手机转为「临时设备」并删除本地凭证；旧 token 再连被拒 |
| AC-37 | 重装恢复 | 卸载重装手机 APP 后扫同一 PC 的码 | 凭 `hardware_id` 识别为常用设备，无需重新勾选「记住」 |
| AC-38 | 终端粘贴 | 在 Linux 终端窗口（如 gnome-terminal）触发自动粘贴 | 发送 Ctrl+Shift+V，文字粘贴成功 |
| AC-39 | 自动发送 | 开启「粘贴后自动发送」后发一条文字到聊天框 | 文字粘贴后自动回车发出 |

### 8.6 验收规则

- 所有 AC 为 **rule 类型**：必须用可复现的命令/脚本/录屏/diff 举证
- 性能类 AC（AC-15~19）需在测试前锁定阈值，测试中不可回调
- 兼容性 AC（AC-27~30）中 Linux X11 为必过项，Wayland/macOS/Windows 为发布前必过项
- 持久配对类 AC（AC-31~39）需双端真机联调验证
- 可靠性 AC（AC-20~22）需真实环境验证，不可用 mock 替代
