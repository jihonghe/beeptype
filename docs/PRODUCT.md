# BeepType 产品文档

> **这份文档管"产品与方向"**：定位、给谁用、竞品与差异化、路线图、明确不做的事、商业化原则。
> 功能规格写到 `docs/PRD.md`，技术实现写到 `docs/TECH_DESIGN.md`；竞品的持续跟踪就放在这里。
> 商业化的**具体战术**（定价数字、收入目标、竞争应对）不写进公开文档，另行记录。

## 1. 一句话定位

**把手机输入法的语音输入，直通任何电脑的光标处。**

跨生态（不挑手机品牌、不挑电脑平台，含 Linux）、电脑端**零客户端**（不装输入法、不下模型、不用买麦克风）、**零云端**（数据只在自己两台设备之间）。

**只做这一件事：手机说话，电脑落字。** 反面参照是 [仓鼠口袋键鼠](https://www.crystal-cloud.top/input/) 那类"手机当遥控器"的产品——语音输入只是它众多能力之一，所以它必须配上键鼠遥控、快捷键、远程启动程序、公网中继和账号。那是**遥控器品类**的必然，不是它的选择（遥控要能用在外网，就必须有中继和账号）。我们的选择相反：**手机当键盘，而且只保留语音这一种输入**——功能单一，换来的是这一件事上尽量没有摩擦。

## 2. 给谁用：需求是分层的

同一件事（在电脑上说话出字）背后其实是几种不同的人，我们只服务其中一层：

| 层次 | 场景 | 主流解法 | 我们 |
|---|---|---|---|
| ① 电脑没麦克风 / 麦克风很差 | 台式机没麦、笔记本麦很破 | 买麦克风；用手机当麦；**讯飞/搜狗输入法自带的「跨屏输入」**（免费，但两端都必须装同一家的输入法） | ✅ 手机就是麦克风，且**不挑输入法** |
| ② 人不在电脑前 | 躺着、沙发上、手机在手上 | 放弃，或者起身去电脑前 | ✅ 手机在手就能说 |
| ③ **已经习惯手机输入法语音的人** | 词库、方言、惯用语都沉淀在手机输入法里 | 在电脑上重装一套 PC 端听写工具 | ✅ 直接复用手机输入法的识别 |
| ④ 不想下模型 / 不想走云 | 本地模型要下几百 MB～GB、云要传音频 | Handy（本地）/ Wispr Flow（云） | ✅ 零模型、零上传 |

**明确不服务的**：要"会议录音转纪要"的（那是 Otter / 讯飞听见一类）；要"在外地用手机流量连家里电脑"的（不做云端中继，见第 6 节）；只要"手机当麦克风"、识别自己在电脑上解决的（那是 WO Mic）。

## 3. 竞品地图：同一个需求被几种形态分流

这个需求**盘子不小**（下面的数据是证据），但被几种形态瓜分了，我们属于其中一种。**3.1–3.4 是可买/可下载的产品，3.5 是免费的内置功能——3.5 那条才是我们真正的价格天花板。**

### 3.1 主流形态一：电脑麦克风 + 本地/云语音识别

| 产品 | 规模（已核实 ✅ / 待核实 ⚠️） | 平台 | 形态 |
|---|---|---|---|
| [Handy](https://github.com/cjpais/Handy) | ✅ 32.0k stars、MIT | Win/macOS/**Linux** | Tauri + 本地 Whisper，按住快捷键说话、松开粘贴到当前应用 |
| Wispr Flow | ✅ [定价页](https://wisprflow.ai/pricing)：免费版桌面 2000 字/周、Pro 15 美元/月<br>⚠️ 数百万 MAU、付费转化 19%、2026-08 拿 2.8 亿美元 B 轮 / 20 亿估值 | Mac/Win/iOS/Android（未见 Linux） | 云端 + 自研模型 |
| VoiceInk | ⚠️ 买断 29/49/69 美元 | 仅 macOS | 本地 Whisper + BYOK |

这一类**用电脑的麦克风**，覆盖的是"电脑有可用麦克风、且愿意装东西/下模型/订阅"的人。

**Handy 的一手实测（2026-09-23，作者本人复测）**：它的**键盘模拟"一坨"，差到让他当时卸载了它——这正是他后来自己做这个产品的起因之一**；改成**剪贴板粘贴后转录"非常准确"**（识别质量与粘贴方式无关，差别全在**送达环节**）。它确实做了"不污染剪贴板"（粘贴后**恢复用户原来的剪贴板内容**，Debug 菜单里有 `Paste Delay (Before)` / `(After)`）——但**他实测那个开关不生效**；而它的文档自己承认原因：**负载下接收方可能在我们恢复之后才读剪贴板，于是粘出旧内容**（issue #502）——**这比污染更糟**。它的修法叫 **"Reliable Paste"**（用"剪贴板读取通知"决定何时恢复，而不是猜固定延迟），标注**仍是实验性**，且**只有 macOS / Windows 有，Linux 没有**。

⇒ **这与我们自己 2026-09-23 的真机实验结论一致**（键盘注入中文丢字且不稳定；X11 自我当剪贴板主人被轮询型管理器击穿——见 `TECH_DESIGN.md` §10.4）。**两方独立、结论相同**：这条取舍可以定案了。

### 3.2 主流形态二：手机当电脑麦克风（只给音频）

- **WO Mic**（⚠️ Google Play 500 万+ 安装、4.0 星、1.76 万条评价）：Wi-Fi/蓝牙/USB 把手机变成电脑麦克风。
- 它的头号差评是"手机息屏后自动断开"（省电机制）——正是我们在续连/判活上花了好几轮的同一个问题。
- **它给的是音频**，拿到之后还得自己找 PC 端识别。我们相当于把这一级和上一级合并成一步。
- **[MicYou](https://github.com/LanRhyme/MicYou)**（✅ 2026-09 核实仓库页：3.9k stars、GPL-3.0、Android 原生客户端 + Windows/Linux/macOS 服务端、WiFi/USB/手机网页扫码三种连接、带 AI 降噪与回声抑制）：把手机做成电脑的虚拟麦克风设备。**它是这一格里规模最大的开源项目**——说明"手机当麦"不是我方独有认知，但它的路径仍是只给音频、识别在电脑侧解决。

### 3.3 主流形态三：硬件语音键鼠（中国市场的付费证据）

- **讯飞智能语音鼠标/键盘**：⚠️ 99 元～699 元、语音约 400 字/分钟、宣称 98% 准确率、部分型号内置离线语音引擎。
- 价值在于**证明中国用户愿意为"在电脑上说话出字"直接掏钱**，只是他们选的形态是"买个鼠标"，而且识别用的是讯飞自己的引擎。

**这一格的共同特征（2026-09 重核后已部分失效）**：PhoneMic / AirType / CatDB 确实都是**个人项目、几十颗星、Windows 优先、手机端是网页、没有签名与正经分发**——但这几条已经不是这一格的全貌：**AirMic** 覆盖 Linux（含 Wayland）/macOS/Windows，**仓鼠口袋键鼠**是公司主体运营、有 ICP 备案、安装包分发、账号 + 订阅。也就是说，"竞品都很弱、都没做正经分发"这个自我安慰**不再成立**。

**CursorLink（✅ 2026-09-22 抓官网全文；同形态里唯一一家已商业化、且走云端中转的产品）**：上海尺锋网络科技有限公司（沪ICP备2026000234号-2，备案号是 2026 年的）。Windows 10/11 客户端约 4MB、macOS 12+ 约 8MB（**客户端版本只有 0.1.0**）、安卓 App（1.0.11）、以及**微信小程序**。**没有 Linux。**

- **机制：模拟键盘注入，而且把"0 剪贴板污染"做成了首页的一格数据。** macOS 的 FAQ 自己写明"需要辅助功能权限才能**模拟键盘输入**"（该软件**未做 Apple 签名**，首次安装要手动授权）。注意区分：它模拟键盘把**内容本身**注入，我们是模拟 Ctrl+V、内容走剪贴板。⇒ 它正好验证了我们上一轮识别出的那条**唯一技术倒退：剪贴板被污染**——而且它把这件事当卖点讲。
- **走云端中转**：FAQ 明确"**不需要**手机和电脑在同一网络"，通过**云端中转服务器**传输，支持跨网络、跨地域；宣称"端到端加密、不存储任何输入内容"。⇒ 这是我们主动放弃的那根轴，**已有第三个玩家在用**（仓鼠、CursorLink）。
- **商业模式：文字免费，图片/文件传输与 AI 功能要会员。** ⇒ 与我们"文本与图片永久免费、不做付费墙"**相反**；但它同时验证了我们的另一条原则——**付费墙不切在核心流程（文字输入）里**。
- **一处真实的渠道差异（2026-09-23 补）**：它的手机端是**微信小程序**——**点开就用、零安装门槛**；我们是 APK，技术用户装得熟（V2EX / 酷安 / Appinn 那批人），普通用户会被"未知来源"挡在门外。**对我们的第一批用户（技术用户）不构成问题，但它是将来破圈时最难补的一块。** 这也是它相对我们唯一一处"结构上更好"的渠道设计——而且它来自"商业模式需要轻入口"，不是设计功力。
- **多设备**：一个小程序可绑定多台电脑、随时切换、配对码一键连接。⇒ 我此前提过的"设备位"方向，它已经这么做了。
- **两条我们没做的**：`/transfer/` 免下载的"临时传输"网页模式；`/ai-suiji/`「AI 随己」——把语音记下的想法交给 AI 整理成"数字分身"。
  - **界面结构（2026-09-23 安卓端截图实测）**：底部四格导航「设备 / 输入 / 随己 / 我的」。**它的"杂乱"大半是它那条路线的必然产物**——有账号 ⇒ 必须有「我的」；按次计费 ⇒ 必须有额度与「使用统计」；有会员 ⇒ 必须有升级入口与邀请返利；有云端功能（随己）⇒ 必须做隐私披露与服务协议；有付费用户 ⇒ 必须有客服。**界面的复杂度是它的约束的影子。** 三条可比的情报：① **「随己」页自己写明"使用此功能需要保存内容到服务器"**——这是"结构性 vs 承诺式隐私"的现成反例；② 它有**手机端发送历史**（「本地发送记录」+「搜索聊天记录」）——正是我们路线图第 3 项要做的东西，它已经做了；③ 它的设置里有 **「输入法确认键：选择显示换行，或直接显示发送」**——说明它也撞上了我们讨论过的"分段提交 / 回车误发"问题，解法是**让用户选回车键的语义**（我们走的是「松手才发」+ 兜底发送键）。
  - **对照我方手机端结构（✅ 代码核实）**：**一共 3 个页面（输入 / 扫码 / 设置），没有底部导航栏**，主页面就是输入。⇒ **简洁不是我方 UI 功力更强，而是"零账号 + 零云端 + 不计费"这个架构选择的红利**——没有东西需要摆在界面上。**这条红利与约束同生共死：一旦引入账号或计费，界面就会开始长东西。**
- **它的主推场景是"AI 协作"**（ChatGPT / Claude / **Cursor** / Copilot）与代码注释——名字里的 Cursor 就是这个意思（即上一轮从 AgentVoice 看到的那个新分支的商业化版本）。
- **⚠️ 早期迹象**：客户端才 0.1.0；官网说"支持 Windows、macOS 双平台"，FAQ 却说"macOS 12+ 即将推出"（自相矛盾）；macOS 未签名。⇒ 它有没有真实用户、留存如何，**无从判断**。

**三个结论**：
1. **思路不新鲜**——"手机输入法识别率更高"是共识（AirType 的 README 明写；CatDB 就是因为"豆包输入法 PC 版还没出"而生的）。我们能领先的不是想法，是**工程厚度与完成度**。
2. **我们多出来的东西**：绑定身份、断线续连、判活、自动粘贴 + 自动回车的**完整交付链**（它们都没做）；以及写**剪贴板 + 粘贴**而不是模拟按键"打字"——中文、emoji、长文本要可靠得多。
3. **"复用手机输入法"仍是独有壁垒**——连形态最像的 AirMic 都走浏览器 Web Speech API，拿不到手机输入法的词库、方言与惯用语；讯飞「跨屏输入」虽然与我们同源，但强制两端都装讯飞输入法。

**竞争格局：两层，别混。**

- **第一层｜形态决定"是不是直接竞争"**。*电脑麦克风 + PC 端识别*（Handy / Wispr Flow / VoiceInk）与我们**错位**——它们服务"在电脑前、有麦、愿意装东西/下模型"的人，我们服务"没麦 / 麦差、人不在电脑前、要用手机输入法词库"的人。**但有一块重叠带**：人在电脑前、有麦、却想要更好的中文识别或手机输入法的 AI 整理——**作者自己就在这块重叠里**（人坐在电脑前，却宁愿拿手机）。*手机 → 电脑光标*（PhoneMic / CursorLink；AirType / CatDB / AirMic 已停更）与我们**直接竞争**：同一批人、同一时刻、同一个动作。
- **第二层｜同一形态里比的是"约束多少 + 可靠性"，不是功能多少**：CursorLink 用云端中继换跨网（代价：账号、订阅、数据过它的服务器）；PhoneMic 免费开源但仅 Windows、手机端是网页；我们跨平台含 Linux、零账号、零中继、不装 PC 端输入法。
- ⇒ **优势分两类，别混**。「**地基**」＝对手要改商业模式才能追：零账号 / 零云端 / 零计费 / 不装 PC 端输入法 / 跨平台含 Linux / 隐私是结构式而非承诺式。「**手感**」＝对手愿意就能追：一个屏幕、不呈现失败状态、输入区默认撑满、不堆技术设置项。**手感是"我们不犯错"，地基才是护城河——守地基、练手感，别把力气花错地方。**
- ⇒ **要盯的三件事各归各家**：需求盘子看 Handy；功能对标 PhoneMic（唯一还在动的同形态）；定位与商业对标 CursorLink（唯一在收钱的，且把首推场景押在"AI 协作"上）。

### 3.5 免费替代（最容易漏掉的一格）：主流输入法自带的「跨屏输入」

**这一格不是产品，是功能——但它才是我们真正的价格天花板。**

- **讯飞输入法「跨屏输入」**（✅ 2026-09 核实）：电脑端和手机端**都必须装讯飞输入法**，两端同网（或登同一账号）→ 电脑端出二维码 → 手机扫码 → 手机输入法说话 → 文字进电脑。免费。有用户反馈偶尔断连。
  - **平台：Windows ✅ / macOS ✅ / Linux ❌。** 讯飞输入法 Mac 版明确把"跨屏语音输入／手机说话电脑打字"列为功能；**没有官方 Linux 客户端**，Linux 这一格是空的。
  - **实现机制（⚠️ 据其专利 CN112684995B「跨屏输入方法及装置」，2020 申请 / 2024 授权）**：扫码配对后**建立"跨屏会话"、把内容以应用层消息推给远端**，专利原文强调"无需输入法或第三方应用进行修改或适配"。⇒ **不经过剪贴板**（这点与我们不同），但也**不是模拟键盘注入**。它能落进任意应用，很可能正是因为它本身**占着 PC 端的输入法位置**（以 IME 提交的方式落字）——这也解释了它为什么必须在电脑上装讯飞输入法。
- **搜狗输入法**有类似能力，社区评价其准确率不如讯飞。
- **对我们的含义**：目标用户（已经习惯手机输入法语音的人）手里**可能已经有**这个东西，而且免费。所以"手机语音 → 电脑出字"这件事本身**不能作为付费点**；付费点必须落在讯飞做不到的地方——**PC 端什么都不装（不用换掉你现在的电脑输入法）、手机用什么输入法都行、文本不经过任何第三方服务器**。

**⚠️ 我们和讯飞不是"谁更强"，是技术取舍不同：**

| | 讯飞跨屏输入 | 我们 |
|---|---|---|
| PC 端前提 | **必须装讯飞输入法并切到它**（要放弃你现在的输入法） | 不碰你的输入法，只跑一个小程序 |
| 手机端来源 | 必须也是讯飞 | 任意输入法（豆包 / 微信 / 搜狗 / 系统自带都行） |
| 文字如何落地 | 应用层会话推送，**不碰剪贴板** | **写剪贴板 + 模拟 Ctrl+V**（终端自动切 Ctrl+Shift+V） |
| 平台 | Windows、macOS | Windows、macOS、**Linux 全平台**（X11；Wayland 里 wlroots 系如 Hyprland/Sway 自动粘贴可用，GNOME/KDE 回退手动粘贴） |
| 代价 | **Linux 没有**；两端都被讯飞锁住 | **污染剪贴板**（每说一句就替换掉你的剪贴板）；需要时序余量（写剪贴板后 50ms、回车前 250ms 起）；Windows 受 UIPI 限制进不了更高权限窗口；GNOME/KDE 的 Wayland 回退纯剪贴板（Wayland 下终端识别不可用，终端里按 `Ctrl+V`） |

**为什么只能这样选：把文字送进光标处只有三条路，每条各交一种税。**

| 路线 | 谁在走 | 它交的税 |
|---|---|---|
| 剪贴板 + 模拟 Ctrl+V | **我们** | **污染用户剪贴板** + 应用异步读剪贴板的时序复杂度（我们代码里 50ms / 250ms 的余量就是给这个的） |
| 模拟键盘把内容本身注入 | **CursorLink**；PhoneMic / AirType 及 Cross-Screen 那类也是 | **长文本可靠性**（掉字 / 错序 / 被输入法截进候选框），焦点不对就失败 |
| 走 PC 输入法的提交通道 | **讯飞「跨屏输入」** | **必须在电脑上装它的输入法**（要放弃你现在的输入法） |

⇒ **第三条对我们不可用**——"不装任何 PC 端输入法"正是我们的卖点。所以我们实际只能在"剪贴板"和"键盘注入"之间二选一：**"零剪贴板污染"不是白捡的升级，是一次换税**（拿剪贴板污染去换长文本可靠性风险）。而**讯飞那条是三条里唯一两条税都不交的**——不污染剪贴板、也不需要逐字注入，因为它占着输入法位置。这就是它作为免费替代最硬的地方。

**键盘注入这条路的优劣（把剪贴板污染那一条抛开不看）**：它的**内容保真能力按平台递减**——macOS 最好（`CGEventKeyboardSetUnicodeString` 是一等 API，直接塞字符串），Windows 次之（逐 UTF-16 单元，emoji 这类代理对与组合序列有风险），**Linux X11 最差**（中文靠临时改写键盘映射，逐字注入，emoji 甚至可能拿不到 keysym）。内容之外它还有三处结构性劣势：

1. **换行没有通用解**——`\n` 映射成 Enter 会变成"边注入边发送"、把一段话拆成多条；映射成 Shift+Enter 又只在聊天软件里成立（编辑器、终端里都不是换行）。而剪贴板路线天然绕开了这个问题：换行是**内容的一部分**，"发送"是另一个独立动作。
2. **副作用**——逐字注入是一串**真实键盘事件**，会触发目标应用的自动补全、自动配对括号、自动缩进、代码片段展开，以及输入法的候选/联想；粘贴则是**一次原子事件**，不触发这些。
3. **失败不可恢复**——剪贴板路线失败时文字还在剪贴板里（用户自己 Ctrl+V 就能救），注入失败则文字既没进光标处、也不在任何地方，只能重说。

它胜出的地方只有两条：**剪贴板不被污染**（它唯一的宣传优势），以及**终端天然支持**（逐字在 vim / ssh / cmd 里通用，可以删掉我们那张 20+ 类名的终端特判表）。

⇒ **综合看：抛开污染这一条，现有剪贴板路线在体验上更优。** 另外值得注意的是，**注入质量最好的平台是 macOS、最差的是 Linux X11**——这与"开发者自己主要在 Linux 上用"的主平台恰好相反。

**顺便否掉一条看上去聪明的路**：既然我们无法避免写剪贴板，那"写完再把我们塞进去的内容删掉"行不行？**不行。** 删除不等于恢复——用户原来的内容在我们写入的那一刻就已经没了，删掉之后剪贴板是**空的**，不是"原样"；而且清空会打破"剪贴板就是兜底、粘贴落空还能 Ctrl+V 救"这条设计不变量（失败就从"可恢复"变成"彻底丢失"），还多一个**不可观测的竞态**（清早→目标应用还没读完剪贴板，粘贴变空；"读完了"没有任何事件可等，我们现在的 50ms / 250ms 就是硬等出来的）。更根本的是：剪贴板管理器（Win+V 历史、Klipper / GPaste / CopyQ、macOS 的 Maccy）在我们写入那一刻就把内容记走了，事后清空**连"零污染"都支撑不起来**。真正的解只有两条：**保存-恢复**（写入前读走、粘贴后写回）或**根本不写**（改走键盘注入，即上表第二种税）。

⇒ 一句话：**我们用"剪贴板被污染 + 时序复杂度"，买到了"不占用你的电脑输入法 + 不挑手机输入法 + 有 Linux"。不是实现更强，是约束更少。**

## 4. 我们凭什么（差异化）

1. **跨生态**：任何安卓手机 + 任何 PC（Windows/macOS/Linux）。手机厂商的多设备协同只服务自家生态，这是它们结构性做不到的地方。
2. **电脑端零条件**：不装输入法、不下模型、不买硬件、不用管麦克风好坏。
3. **识别质量来自手机输入法，而且自动跟着它的升级曲线走**：用户自己的词库、方言、惯用语都在那儿，比电脑上现装的小模型更懂他；更关键的是，**输入法厂商正在为语音军备竞赛（AI 纠错、口语整理、长文模式）**，这些能力会**自动**流到我们这边——我们一行模型代码都不用维护。对照：Handy 的识别质量受限于**用户下载的本地模型**与 Whisper 的发布节奏。
4. **工程厚度**：绑定/续连/判活/自动粘贴/自动回车的完整链——同类个人项目都停在这一层之前。
5. **交付方式稳**：文字先落剪贴板再谈自动粘贴，剪贴板是所有桌面环境的最低公约数。
6. **可验证的隐私**：零云端；若核心开源，这句话是**可被验证**的，而不是一句声明。
7. **不呈现失败状态，只呈现下一步**：连不上就直接进扫码页，而不是留在原地显示"未连接" + 让输入框变灰。用户不需要理解"为什么连不上"，只需要知道下一步做什么。对照 CursorLink：未连接时给的是「未连接设备」+ 灰掉的输入框 + 一大片空白 + 一个抢眼的客服按钮——**用户得自己猜下一步该去哪**。
8. **一个屏幕就够**：已连接时手机上**只有三样东西**（顶栏 / 连接胶囊 / 输入区），没有底部导航、没有额度条、没有会员卡、没有客服。**这是"零账号 + 零云端 + 不计费"的红利**——没有东西需要摆在界面上（详见 §3.4 对 CursorLink 界面复杂度的归因）。
9. **扫码即用、无需绑定（临时连接）**：**这条不能砍**，因为它承担两个不可替代的职能——① **它就是"试用通道"**：第一次用不需要注册、不需要绑定任何东西，扫码即可试。对照 CursorLink（微信登录）与仓鼠口袋键鼠（微信登录）**都要求账号**——那是它们要收钱、要算成本才付的代价，我们不需要付；而同形态的 PhoneMic / AirType / CatDB 全是"扫码即用、无绑定"⇒ **砍掉它，我们反而比对手多一道门槛**。② **它是"不留痕"这个隐私诉求的唯一落点**：剪贴板污染在**自己的电脑**上根本不是隐私问题（就是你自己剪贴板多一条字），只有在**别人的电脑**上才是 ⇒ **砍掉临时连接，"不留痕/标记法"整条议题立刻贬值到不值得做。**
   - 随之而来的责任：既然留着，**"临时"就必须真的是临时**——用完就走、退出后不留席位 / 凭证 / 标记（§4 自查第 3 条）；且**别让它变成主路径**（胶囊只在临时连接时标「临时」，这个设计已经做对了：让用户知道这是临时状态）。
10. **如实告知代价，而不是承诺一个做不到的能力**（2026-09-23 定）——对外**不写**"不污染剪贴板"，而是用人话把代价写清：**"每次说话，你电脑的剪贴板会被替换成这段文字。"** 位置：官网 / 仓库首页一句话（不是只有开发者会看的 README 深处）+ **首次使用时能看到**。
    - **理由有两层**：① **"用户自己取舍"的前提，是他知道自己在取舍什么**——不告知，"让用户取舍"就退化成"用户不知道自己在取舍"；② **告知本身就是差异化**——一个明说"我会临时占用你的剪贴板"的产品，比一个偷偷污染的更可信；这与"不需要你相信我们、你可以自己看（开源）"是同一套逻辑（对照 CursorLink 的隐私是**承诺式**的）。
    - **代价可以被减小，减小代价 ≠ 背弃取舍**：见 §5 第 6 项的「保存-恢复」——它把"你原来复制的东西永久丢了"这个（自己电脑上最高频的）痛点消掉，成本约为注入的十分之一。
    - **⚠️ 2026-09-23 追加：不能说"不告知"**（他提过"尽量做到不进剪贴板、但不告知用户"，**否**）：① **"可能做不到"恰恰是必须告知的理由**——不告知 + 结果不确定＝让用户在自己不知情的情况下承担后果；② 标记法**在 Windows / macOS 会生效，在你的 Linux（Deepin/DDE）上不生效**——你的剪贴板管理器是 `dde-clipboard`，代码检索确认它**不认任何标准机密标记** ⇒ 这个平台差异用户更该知道，否则他会以为"在哪都不留痕"；③ 实用价值：不告知时，用户发现"我刚复制的东西没了"会**归因错误**、以为是产品 bug，你白丢一次建立信任的机会；**告知把一次"抱怨"变成一次"预期兑现"**。
    - **"尽可能进不了剪贴板"已经试到尽头（三条路都有结论，别再重走）**：**标记法**＝Win/mac 的官方机制会生效**但尚未实现**（因 Linux 探针失败而挂起），你的 Linux 上**无效**；**X11"主人策略/瞬态"**＝已实现、**真机证伪、已回滚**（`9f9e7fb`）；**注入模式**＝真机实测**中文丢字且不稳定、已暂停**。⇒ **"尽可能"的正确形态只有标记法**（能生效就生效、不生效就退化成普通剪贴板——**不改变行为、没有随机性、最坏结果是"没效果"而不是"出问题"**），**绝不是"有时改用注入"**：那会让同一个动作出现两种行为，而注入的失败是**随机**的（丢哪个字每次不一样），违反他自己定过的"**行为统一优先于单点体验优化**"（他否掉"松手才发"B 方案时用的就是这条）。
    - **所以文案现在只需要一句**：**"我们会临时占用你的电脑剪贴板。"** 等标记法真在 Windows / macOS 上实现了，再补"同时标记，让系统与主流剪贴板管理器不记录它"。**没实现的能力一个字都不写**——这正是本条纪律本身。
    - **⚠️ 要警惕的滑坡**："用户能接受"是**最低标准，不是目标**。它不能变成"所以这里不用再打磨"的挡板——这与既有的"不为不常见的问题加机制"**不是一回事**：那条针对**罕见**，这条容易滑成**不用管**。
7. **手机端是原生 App，不是一个网页**（同类里除 CursorLink 外，PhoneMic / AirType / CatDB / Cross-Screen / AirMic 的手机端**都是网页**）。这不只是观感：**网页拿不到输入法的 composing（正在输入）状态**，所以"松手即发"这个手感、以及按段提交的判断都做不出来；相机扫码、被杀后台后的续连、剪贴板兜底同样都依赖原生能力。⇒ 手机端的体验差距是**结构性的**，不是打磨出来的。

**⚠️ 要打"隐私"这张牌之前，先把所有隐私面审一遍——不能只修剪贴板。** 四个面：

1. **PC 端日志会不会打印正文？**（最容易被忽略，也最容易在自己的机器上查。日志里有正文的话，"不留痕"就是自欺。）
2. **临时连接的传输是否加密？** 在别人的网络里，同网段的人能不能嗅到载荷？（配对码与凭证校验只解决"谁能连"，不等于载荷保密。）
   - **✅ 已核实（2026-09-23 读代码）**：① **日志不打印正文**——抽到的是"记录了行的**字节数**"、"记录了 peer IP / 消息 id / 错误"，**没有把文本内容写进日志**（唯一残留疑点：`Parse error` 那条的 `e` 会不会带内容片段，值得再看一眼）。② **载荷未加密**——Rust 侧只有 `sha2`、Dart 侧只有 `crypto`（都是哈希，用于凭证 / 硬件指纹），**没有任何 AEAD / TLS / 密钥交换的依赖或实现** ⇒ **同一局域网里明文可被被动嗅探**。⇒ **这是隐私面里唯一目前可查实存在的洞**，处理方式见第 5 节第 7 项。
3. **在别人电脑上留下了什么状态？** 临时连接结束后，那台 PC 上还留着席位 / 凭证 / 设备记录吗？**如果它还记着"这台手机连过这台电脑"，那比剪贴板更严重**——"用完就走"必须是真的。
4. **手机端将来存历史吗？**（第 5 节的「手机端输入控制台」要做）那也是持久存储，只是手机属于自己、风险等级低一些。
5. **识别那一步的音频走了谁？** 手机输入法的语音识别**通常在输入法厂商的云上跑**——音频离开了设备（除非用户开离线识别），而输入法的 AI 整理还可能把文本再上传一次。⇒ **"零云端"只能精确表述为"文本传输零云端"**，绝不能说成"什么都不上传"。**Handy 的本地 Whisper 在这一条上比我们干净**——这是"隐私"这张牌唯一的软肋，别被对手抓到。

**这五条里任何一条不干净，"隐私"这张牌就打不响**；而其中第 2、3 条的后果可能比剪贴板更严重。**"我们比讯飞、CursorLink 更懂隐私"这句话，得先经得起这五条自查**——而且这正是我们相对它们的结构性优势所在：它们的隐私是**承诺式**的（端到端加密、我们不存储——但文字必须经过它的中转服务器，你得相信它），我们的可以做成**结构性 + 可验证**的（数据根本不经过任何服务器 + 代码可查）。

## 5. 路线图（按优先级）

1. **自定义键位（粘贴键 / 发送键）**——他 2026-09-23 提，设计已定、**先入路线图**：
   - **默认**（现状已如此、不用重做）：粘贴键普通应用 `Ctrl+V`（macOS `⌘V`）、识别到**终端自动切 `Ctrl+Shift+V`**；发送键 `Enter`；
   - **要加的是「自定义口子」**：**普通应用与终端各一组**（键位天然分两套环境），每组各选粘贴键与发送键 —— 粘贴键 `Ctrl+V / Ctrl+Shift+V / Shift+Insert`（**Shift+Insert 兼容最广**：Windows Terminal、conhost、xterm、mintty、VS Code 内置终端都认）；发送键 `Enter / Ctrl+Enter / ⌘+Enter / 不自动发送`；
   - **做成「选项列表」而不是自由输入**（覆盖 99% 需求、不可能配出非法状态、成本低一个数量级；竞品 Handy 也是列选项）；
   - **不做**按应用的键位名单（应用内可各自设置、且会腐坏，与既有决定一致）；
   - **识别边界**：只到窗口级 ⇒ **IDE 内置终端认不出**（会当普通应用处理）；识别到终端用终端那组、认不出用普通那组；
   - **已定（他 2026-09-23 拍板）**：终端那一组的**发送键默认「不自动发送」**（键位仍是 Enter，只是不在终端里自动按；想开就在设置里选 Enter）——理由：终端里 Enter 是"执行命令"，这是唯一可能造成真实损失的场景。
2. **手机端输入控制台**——历史记录、编辑后重发、发送失败不丢原文。
3. **iOS 适配**——原生通道代码已就绪（Keychain 硬件指纹、设备名、版本号），缺的是一台 Mac、一部真机和开发者账号，以及真机验证与分发。
   - **上架口径**：iOS **只能**走 App Store（TestFlight 会过期、企业签名灰、侧载不现实）⇒ 这不是"要不要上架"的选择，而是"**要在 iOS 上存在，就得这么做**"。99 美元/年是**年年续费的支出**，换到的是"用户敢装、能装、自动更新"——**不是曝光**（商店不会给人用户，用户来源仍然是社区与口碑）。对不打算赚钱的产品，这是**现金流问题，不是理念问题**。
   - **桌面端与 App Store 无关，别混在一起想**：macOS 桌面端要辅助功能/注入，几乎肯定过不了审核（Guideline 2.4.5，见第 7 节"已否掉的收费方向"），走**官网 + Developer ID 公证**；Windows / Linux 各有各的常规分发（exe+签名 / deb+AppImage+Flatpak+AUR）。
   - **⚠️ 必须提前设计「审核模式」**：App Store 审核员要能完整跑通核心功能，而本产品**单独在手机上什么也做不了**——它必须连上一台装了桌面端的电脑（同一局域网），而审核员不会去装你的程序并配对。⇒ 要在 App 内提供一条**不依赖 PC 的演示路径**，或至少备好演示视频 + 审核备注里的详细说明。**这是设计工作，不是运气**（依赖外部硬件的 App 都是这么过的）。
4. ~~**Wayland 会话的自动粘贴**（探路）~~ —— **✅ 2026-10-18 已做**（触发条件正是"他自己的主力机换成 Omarchy/Hyprland"）：`paste.rs` 的后端判定改为**能力探测**（`wayland_input.rs` 读合成器注册表，看有没有 `zwp_virtual_keyboard_manager_v1` / `zwp_input_method_manager_v2`），有则打开 enigo 的 wayland 后端走虚拟键盘协议，没有（GNOME/KDE）自动回退纯剪贴板。**实测在 Hyprland 0.56 上自动粘贴/自动发送可用**；遗留：Wayland 下拿不到焦点窗口 ⇒ 终端识别失效（一律 `Ctrl+V`），出口是「自定义键位」。
5. **不留痕的使用方式**（原"剪贴板污染的缓解"，候选）——**来源已从"设想"升级为他本人的真实诉求（2026-09-22）**：他的场景是**公共 PC / 临时连接别人的电脑**——剪贴板是共享且持久的通道，他说的字会留在那台机器上，**下一个用这台电脑的人 Ctrl+V 就能看到**。⇒ 这也解释了 CursorLink 为什么把"0 剪贴板污染"当卖点：**它真正要卖的是隐私**。
   - **⚠️ 结论先行（2026-09-23 真机实测后）**：**本条下面提到的两条替代路（键盘注入、瞬态剪贴板）都已实测否决并已回滚**（见本条末尾，与 `TECH_DESIGN.md` §10.4）⇒ **唯一还站着的方向是「标记法」**。以下推理过程按原样留档，别再重走。
   - **仍然先做便宜的「保存-恢复」**（写入前读走用户剪贴板、粘贴后写回）：成本约为键盘注入的十分之一、同属剪贴板路线、不新增交付子系统。**但它治的是"我刚复制的东西被覆盖了"，不治"我的字留在了这台机器上"**（Win+V 历史、Klipper / GPaste、Maccy 在我们写入那一刻就记走了）⇒ **对他的隐私诉求，它不够。**
   - **✗ 已否决（2026-09-23 真机实测，见本条末尾）——当时以为"真正满足该诉求的只有键盘注入"**。
   - **一个有利的对齐**：别人的电脑几乎必然是 **Windows / macOS**——恰好是注入质量最好、且 enigo 已实现 `fast_text` 的两个平台；而注入最差的 **X11 正是他自己的常用机**，那里并不需要隐私模式 ⇒ **技术上可以不做 X11 注入。** 但**他只能在自己拥有、且能真机验证的平台上做**（红线：先真机验证再发版）——有没有 Windows 机器可用于验证，决定这条路现在能不能走。
   - **前置条件**：注入失败不可恢复 ⇒ **必须同时有手机端历史 / 重发（第 3 项）**。
   - **⚠️ 2026-09-23：两条路都试过，都不采用（已回滚）**——① **X11 上自己当剪贴板主人**：机制本身有效（接管后所有读取都能拒 ✓），但**对"轮询型"管理器无效**——实测 DDE 的 `dde-clipboard` 是**内容变化后 50ms 才开始、每 50ms 轮询一次**，而我们的"放行"为了粘贴必须在写入后约 1ms 打开 ⇒ 它的请求全落在放行之后 ⇒ 照样拿到（真机日志为证）。要挡它就得连粘贴后也不放行，那会让用户手动 Ctrl+V 彻底失效，与"剪贴板是兜底"冲突。② **键盘注入**（完全不碰剪贴板）：真机实测（`examples/inject_probe.rs`）**中文丢字、且不稳定**（每次丢的字不一样）⇒ 准确度不可接受，**暂停探索**（它没有剪贴板那样的读回校验，丢了也不知道）。**结论：剪贴板 + 粘贴仍是唯一可靠稳定的投递方式**；"不留痕"若要继续，只能等更底层的手段（Wayland 门户 / 系统级 IME 通道）。详见 `TECH_DESIGN.md` §10.4。
   - **呈现方式**：不要做成"技术二选一"，而是**按情境**——默认"我自己的电脑"（剪贴板，体验最好），另设一项**"在别人的电脑上使用 / 不留痕"**（注入）。用户该选的是他知道的情境，而不是他无法预判后果的技术权衡。

   - **三个档位（2026-09-22 补，回答"能不能既不留痕、又继续用剪贴板"）**：
     - **A 档｜根本不写剪贴板**（键盘注入）：唯一真正的零足迹。代价见前文（可靠性 / 失败不可恢复 / 换行无通用解）；**而且它不解决日志、传输、临时连接遗留这三个面** ⇒ **"换成注入"≠"隐私安全"**。
     - **B 档｜瞬态剪贴板**（写入 → 立即粘贴 → 随后恢复原内容）：暴露窗口从"永久"压到几十～几百毫秒，**能挡住"下一个用这台电脑的人 Ctrl+V 就看到"这个具体画面**，但**挡不住剪贴板管理器 / 剪贴板历史**（它们在我们写入那一刻就记走了）。工程增量极小（同属剪贴板路线，只多一步"撤"）；风险是撤早了会让粘贴拿到**原内容**（比空粘贴更糟），而这个时序**不可观测**。
     - **C 档｜X11 特有的"真零足迹剪贴板"**：X11 的剪贴板不是共享缓冲区，而是**"所有权 + 按需提供"**协议——数据只活在我们进程内存里，谁请求、给不给、给几次都由我们决定 ⇒ 可以做到**只服务一次、且只在我们注入 Ctrl+V 之后**，此前的请求（含剪贴板管理器在所有权变更时的抓取）一律拒绝。**这是三个平台里唯一能做到零足迹的实现**；Windows / macOS 的剪贴板是"推进共享内存"，只能停在 B 档。**讽刺的是：唯一能零足迹的平台（X11）恰恰是不需要隐私模式的那台机器。**
     - ⇒ 对"别人的 Windows / macOS 电脑"这个场景，真正的选择只有 **A 档**或 **B 档**——**B 是"防手滑"级别的隐私，A 是"防取证"级别的隐私。**

   - **⚠️ 上面那套 A/B/C 三档已被 2026-09-23 的真机实测改写：A（注入）与 C（X11 零足迹）都试过、都不成立，B（瞬态）也被 Handy 的官方文档与我们的 X11 实测两面夹击 ⇒ 请直接读下面这一档。**
   - **补一档（2026-09-23 另一会话核实）：敏感标记法**——仍是剪贴板路线，但写入时**附带"机密"标记**，让系统与主流剪贴板管理器**不记录、不同步**：Windows 有三个官方格式（`ExcludeClipboardContentFromMonitorProcessing`、`CanIncludeInClipboardHistory=0`、`CanUploadToCloudClipboard=0`，见[微软文档](https://learn.microsoft.com/en-us/windows/win32/dataxchg/clipboard-formats#cloud-clipboard-and-clipboard-history-formats)；密码管理器与 Chrome 无痕模式都这么做）、macOS 有 `org.nspasteboard.ConcealedType`、X11 有 `x-kde-passwordManagerHint=secret`（Klipper 认）。**它正好把上面 B 档"挡不住剪贴板管理器 / 历史"这条补齐**（Windows/macOS 上），而且**保持剪贴板的全速与可靠、永不丢内容**（内容仍在"当前剪贴板"里，用户随时能 Ctrl+V）；**与瞬态剪贴板叠加**＝连"下一个用这台电脑的人"也挡住。⇒ 于是选择可以更简单：**标记法（覆盖历史与云同步）+ 瞬态/只服务一次（覆盖"当前剪贴板"）**，注入模式留给真正要"防取证"的场景。
     - ⚠️ **命名冲突**：本会话先前讨论的"A 档"指的是**标记法**，与本文档此处 A/B/C（注入 / 瞬态 / X11 零足迹）**不是同一套**。后续统一叫 **「标记法」「瞬态剪贴板」「注入模式」**，不再用字母档。
     - 三平台改法、代码量、Linux 探针与实施顺序，已单独记入工作区记忆（本机私有，不进仓库）。
     - **它是默认开启项，不是设置项（2026-09-23 定）**：标记法**不改变交付路径、不牺牲可靠性、用户无感**（内容照常进"当前剪贴板"、照常能 Ctrl+V、速度不变）⇒ **没有代价的事不需要让用户选**；做成设置项反而会让用户以为"走剪贴板是个有风险的技术开关"。⇒ **对外措辞不能说"100% 不污染"**（标记法是**协作协议、不是强制**——不配合的管理器照样记录；而且"当前剪贴板里那一刻就是你的字"永远消除不了，因为它必须走剪贴板才能粘贴），只能说"**主流剪贴板管理器与系统历史不会记录**"（这正是 §4 第 10 条那条纪律的直接应用）。**另注：Linux 并非做不到**——X11 有 `x-kde-passwordManagerHint`（Klipper 认，CopyQ 也认 Windows 那几个格式）⇒ **三平台都有对应机制，区别只是覆盖率**（遵守协议的被覆盖，不遵守的覆盖不到）。
     - **只有"零足迹＝从不写入"才需要给用户选择**：那要靠**注入模式**（以可靠性换，且当前实测已否决）。等将来在 Windows / macOS 上真有机器、真机验证过、且注入可用时，它才是一个**情境选择**（"在别人的电脑上使用"），而不是"技术二选一"。

     - **独立佐证（2026-09-23）：Handy（32k★、开源）撞到了同一个结论**——它的键盘模拟难用到让用户卸载、剪贴板模式才准；它做了"粘贴后恢复原剪贴板"，**官方文档却承认负载下会粘出旧内容**（issue #502），修法（Reliable Paste）标着 Beta 且仅 macOS / Windows。⇒ 与我们的真机实验**互为独立验证：注入与瞬态剪贴板两条路都不成立**，唯一还站着的方向是「标记法」。
     - **由此得一条纪律**：**Handy 那个"不污染剪贴板"的开关对外宣传、实测不生效** ⇒ 我们那条"**先真机验证再发版**"的红线**对文案同样适用——没验证过的能力，一个字都别写进宣传**。

6. **传输加密**（质量类，不是新功能）——**核实结果：现在载荷是明文的**（Rust 侧只有 `sha2`、Dart 侧只有 `crypto`，都用于凭证 / 硬件指纹；没有任何加密依赖或实现）⇒ **同一局域网里可被被动嗅探**。
   - **它补的是"链路上被看"，与「不留痕」补的"本机残留"是两个面**，不能用一个换另一个。
   - **而且它的适用场景比不留痕更广**：要用**别人的电脑**才需要不留痕；而**用自己的电脑、走到别人的网络上**（公司网 / 咖啡厅 / 酒店 / 共享办公）就已经需要它 ⇒ **优先级可能比不留痕还高**（临时连接场景与"别人的网络"高度重合）。
   - **成本可控且有现成设计**：两端都是我们的，配对时已经有共享秘密（高熵配对码 / 凭证）⇒ 可以**从配对秘密导出对称密钥 + 用 AEAD 加密载荷**，不需要 PKI、没有证书要信任、**用户完全无感**。

**打磨的两个输入源（判据不同，别混）**：
- **体验类**：来自他自己**真实撞上的摩擦**（行为证据——见第 6 节判据）。
- **安全类**：来自**威胁模型**——他日常不会"撞上"被窃听，所以安全项**不能靠体感发现**，只能靠主动列清单：同网段窃听 / 伪造 PC 端（冒充接收方）/ 重放旧凭证 / 手机丢失后被他人使用 / 电脑上别的程序冒充我们的服务端。

### 已完成（移出路线图，细节留档）

- **发送延迟**（2026-09-23 随 `v0.7.1` 发布）：实现方式不是"静默 T 毫秒"，而是**「松手才发」**——手机端按**麦克风占用状态**判定（录音期间一律不发送，松手后"还有没提交的字就等它、没有就立刻发"），微信/豆包/讯飞/搜狗四款实测行为一致。唯一残余价值是"读不到录音状态的机型"（老系统匿名化 / iOS），那些机型退回旧行为。
- **GitHub Release 自动构建**（CI）。
- **图片传输**（✅ 2026-09-23 已随 `v0.8.0` 发布并真机验证）——手机选图 → **电脑剪贴板里就是这张图** → 在聊天框 Ctrl+V 直达（开着自动粘贴就直接落进去）。核心场景：把手机截图发进电脑上的聊天窗口。**⚠️ 需求待验证**：本产品自己的实际使用几乎全是"语音转文字"，图片传输尚未在真实场景里被反复用到 ⇒ 按 §6 的判据（"要用它的那一刻，没有会不会很难受"），它现在还**不构成**核心流程内部的断裂。做它成本小，但不该排在"让这个产品更好用"之前。
   - **实现与隐私约束（2026-09-23 补，别搞错）**：**图片也必须走剪贴板。** Ctrl+V 只会从剪贴板取内容，没有第二条路 ⇒ 流程是「手机 →局域网→ **PC 端程序内存暂存** → **写进剪贴板（图像格式）** → 模拟 Ctrl+V」。**"暂存在 PC 程序里"是为了写进剪贴板，而不是替代剪贴板。** 三个后果：
     ① **图片不避开剪贴板污染，它是加重污染**——文字污染是"换掉你复制的一段字"，图片污染是"换掉你的剪贴板内容，而且可能是几 MB 一张图"，用户更容易察觉、也更烦 ⇒ 做图片让「标记法 / 瞬态剪贴板」从加分项变成**必需项**。
     ② **新增一条隐私面**：图片要在 PC 端暂存，若实现成**临时文件落盘**，那台电脑的磁盘上就留下你的图片——"用完就走"在图片上破功 ⇒ **设计约束：图片全程内存缓冲、不落盘**（这条现在就要定，它决定用流式分块还是全量内存）。
     ③ **图片进剪贴板后，不粘贴就留在那儿**：对文字我们说"剪贴板是兜底"（用户还能 Ctrl+V 救），对图片它是**更强的暴露**（截图常含敏感信息、体积大、显眼）。
   - **好消息**：Wayland 下（wlroots 系）自动粘贴可用，图片随文字一起自动贴出；GNOME/KDE 回退"纯剪贴板 + 手动 Ctrl+V"时，图片一样能用（用户自己粘图），所以图片不引入新的平台缺口。


## 6. 明确不做

**加功能的判据（2026-09-22）**：一个额外功能该不该做，不看它本身多有用，而看**"要用它的那一刻，如果没有会不会很难受"**——也就是它的缺席会不会在**核心流程内部**造成断裂。图片传输符合这条：动作是同一个（"我手机上有东西，想让它出现在电脑上"），只是内容从文字变成了图。**别用"剪贴板能承载什么"当判据**——剪贴板也能承载**文件列表**（Windows 上复制文件时剪贴板里放的是 `CF_HDROP`，粘进聊天框就变附件），那个判据会把文件放进来。正确的判据是"**它能不能在光标处作为一个内容出现**"：文字、图片能；文件不能（它出现在附件槽里）。

- **不自建语音识别引擎**——复用手机输入法，这是产品的地基。
- **不做云端中继**——纯局域网；跨网络（在外地用流量）不在产品范围内，因此也不为它引入账号与服务器。
- **不做账号体系**——收费走离线许可证；账号只在将来真有云功能时才有意义。
- **不做剪贴板/图片的历史管理**——那会把产品变成文件或剪贴板管理器，破坏"直达输入位置"的简洁模型。
- **不做通用文件传输**——图片是唯一例外。分界线不是文件格式，而是**图片是"输入"、文件是"附件"**：图片跟文字同级，走同一条"剪贴板 + 粘贴"通道、一个动作就完成；文件体积不受控，需要进度、失败重传、断点续传，那是 LocalSend 一类工具的活。（技术上"能接图片的输入框就能粘贴文件"基本成立——剪贴板里放的是文件路径——但这不构成该做的理由。）做了它，产品就从"直达输入位置"变成"文件传输工具"。
- **2026-09-23 追加：不做文件传输的理由补充**（他提出"缝合 LocalSend"以吸引更多用户，**已否**）——① **需求是真的**（他在用 LocalSend 传图/传文件），但**问题不是需求真假，而是"我们做的会不会比 LocalSend 更好"**：不会，它是成熟的多平台开源工具，我们做一遍只会更差；而"只用这一个 App"是**弱价值**——**没有人会为"顺便也能传文件"换工具**。② **"吸引更多用户"＝用功能解分发问题**（已确认：上架和功能都不带来用户，用户来源是社区与口碑）。③ **文件必须落盘**（几十 MB～GB 不可能全内存），与图片那条"全程内存、不落盘、用完就走"的约束**正好相反** ⇒ 会在别人的电脑上留下真实文件，直击隐私定位。④ **它会把产品定义撑破**：文件传输 → 接收历史 → 传输列表页 → 底部导航——**这正是 CursorLink"四格导航"的起点**，会吃掉"一个屏幕就够"的红利。
  - **一条更可操作的判据（替代"输入 vs 附件"的说法）**：**"它能不能复用现有的交付链（剪贴板 + Ctrl+V）？"** 文字能、图片能（图片本来就是"写剪贴板 + 粘贴"）；文件不能（要进度 / 落盘 / 断点续传）⇒ 它不是"多一个载荷"，是**再开一条交付链**。
  - **实证路径（代替替他判断）**：先把图片做完，然后**留意他自己一个月里还用了几次 LocalSend**——那是行为证据，符合他自己定的判据体系。
- **不做远程控制**（鼠标/键盘/屏幕）。
- **不做遥测**，不做打扰式更新提示。
- **不为"语音识别特性差的输入法"做按品牌适配**——改进放在与输入法无关的方向上（例如第 5 节的「自定义键位」）；差的输入法该被淘汰，我们只需不惩罚它。
- **不为不常见的问题加机制**。

## 7. 商业化：目前看不到收费路径

**2026-09-22 评估结论：在当前形态下看不到收费点，倾向"免费开源 + 接受捐赠"。** 三条理由：

1. **没有升级空间**——核心功能本身已经足够好用，谈不上"有什么高级功能比它更好用"。单点产品的升级空间来自"更多 / 更贵 / 更快 / 更省心"，这四样本产品都不需要。
2. **成本结构是零**（无云、无 GPU、无模型）⇒ 它不需要收入来存活，也就没有非收不可的理由。
3. **免费替代已经够多**——讯飞「跨屏输入」免费、Win+H 免费、同类 Handy / PhoneMic / AirType / CatDB 全是免费开源 ⇒ 收不到。

⚠️ 这个结论是在**零用户**的位置上得出的：**收费是分发之后才可能出现的问题**。若将来真有一群人用起来、并且反复要同一个"更多 / 更大 / 更好"，那时再重新评估——而不是现在去设计它。

**已经否掉的收费方向**（记下来，免得重走）：

- **走苹果开发者平台、只做 iOS / macOS 专属版**：(a) 输入注入类 Mac 工具很可能过不了 Mac App Store 审核（要"辅助功能"权限，App Review 按 Guideline 2.4.5 拒，剪贴板管理器有被拒的公开先例），现实路径是官网分发 + Developer ID 公证，**App Store 的收款通道帮不到桌面端**；(b) 会放弃需求最集中的 Windows 与安卓——同类产品全是 Windows 优先，而唯一可见的付费证据（讯飞语音鼠标）买的正是"Windows 电脑 + 安卓手机"这个组合。
- **设备位 / 限额类收费**：在"一部手机 + 一台电脑"的产品里，限制是人为造出来的，不成立。
- **⚠️ 后到的反证（2026-09-22，需他复核）**：**CursorLink**（同形态、已商业化的产品）做的是**文字免费 + 图片/文件传输收费（会员）**——与本节的"文本与图片永久免费"**相反**；**仓鼠口袋键鼠**也把图片/文件等捆进付费。⇒ **"图片该免费"不是市场共识**，这条判断目前的市场样本是空的、甚至反向的。原判断（图片属核心流程的补齐）暂时保留，但标注为**待他复核**。

**以下原则仅在"若将来真出现收费路径"时成立：**

- **文本与图片永久免费**：免费版就是完整可用的产品，口碑与传播靠它；隐私卖点靠"代码可见"来证明。
- **付费不切在核心流程内部**：图片传输属于**核心流程的补齐**（见第 6 节的加功能判据），因此**不做付费墙**。它跟文本桥是同一种价值——"把手机上的东西少几步弄到电脑上"，只是载荷从文字换成图；而且免费的替代品已经在用户手里（微信文件传输助手、LocalSend），痛点从来不是"做不到"，是"要四步"。⇒ 文本与图片都该在免费版里完整可用。
- **收费形态：一次性买断的离线许可证**——不做账号订阅（无服务器、不收集用户信息、心智简单）。
- **顺序**：先把核心体验做扎实（第 5 节的「手机端输入控制台」这类），iOS 适配与"是否收费"都在那之后再说。
