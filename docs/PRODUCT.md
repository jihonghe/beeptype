# BeepType 产品文档

> **这份文档管"产品与方向"**：定位、给谁用、竞品与差异化、路线图、明确不做的事、商业化原则。
> 功能规格写到 `docs/PRD.md`，技术实现写到 `docs/TECH_DESIGN.md`；竞品的持续跟踪就放在这里。
> 商业化的**具体战术**（定价数字、收入目标、竞争应对）不写进公开文档，另行记录。

## 1. 一句话定位

**把手机输入法的语音输入，直通任何电脑的光标处。**

跨生态（不挑手机品牌、不挑电脑平台，含 Linux）、电脑端**零客户端**（不装输入法、不下模型、不用买麦克风）、**零云端**（数据只在自己两台设备之间）。

**只做这一件事：手机说话，电脑落字。** 反面参照是 [仓鼠口袋键鼠](https://www.crystal-cloud.top/input/) 那类"手机当遥控器"的产品——语音输入只是它众多能力之一，所以它必须配上键鼠遥控、快捷键、远程启动程序、公网中继和账号。那是**遥控器品类**的必然，不是它的选择（遥控要能用在外网，就必须有中继和账号）。我们的选择相反：**手机当键盘，而且只保留语音这一种输入**——功能单一，换来的是这一件事上尽量没有摩擦。

## 2. 给谁用：需求是分层的

同一件事（在电脑上说话出字）背后其实是几种不同的人，我们只服务其中一层：

| 层次 | 场景 | 主流解法 | 我们 |
|---|---|---|---|
| ① 电脑没麦克风 / 麦克风很差 | 台式机没麦、笔记本麦很破 | 买麦克风；用手机当麦；**讯飞/搜狗输入法自带的「跨屏输入」**（免费，但两端都必须装同一家的输入法） | ✅ 手机就是麦克风，且**不挑输入法** |
| ② 人不在电脑前 | 躺着、沙发上、手机在手上 | 放弃，或者起身去电脑前 | ✅ 手机在手就能说 |
| ③ **已经习惯手机输入法语音的人** | 词库、方言、惯用语都沉淀在手机输入法里 | 在电脑上重装一套 PC 端听写工具 | ✅ 直接复用手机输入法的识别 |
| ④ 不想下模型 / 不想走云 | 本地模型要下几百 MB～GB、云要传音频 | Handy（本地）/ Wispr Flow（云） | ✅ 零模型、零上传 |

**明确不服务的**：要"会议录音转纪要"的（那是 Otter / 讯飞听见一类）；要"在外地用手机流量连家里电脑"的（不做云端中继，见第 6 节）；只要"手机当麦克风"、识别自己在电脑上解决的（那是 WO Mic）。

## 3. 竞品地图：同一个需求被几种形态分流

这个需求**盘子不小**（下面的数据是证据），但被几种形态瓜分了，我们属于其中一种。**3.1–3.4 是可买/可下载的产品，3.5 是免费的内置功能——3.5 那条才是我们真正的价格天花板。**

### 3.1 主流形态一：电脑麦克风 + 本地/云语音识别

| 产品 | 规模（已核实 ✅ / 待核实 ⚠️） | 平台 | 形态 |
|---|---|---|---|
| [Handy](https://github.com/cjpais/Handy) | ✅ 32.0k stars、MIT | Win/macOS/**Linux** | Tauri + 本地 Whisper，按住快捷键说话、松开粘贴到当前应用 |
| Wispr Flow | ✅ [定价页](https://wisprflow.ai/pricing)：免费版桌面 2000 字/周、Pro 15 美元/月<br>⚠️ 数百万 MAU、付费转化 19%、2026-08 拿 2.8 亿美元 B 轮 / 20 亿估值 | Mac/Win/iOS/Android（未见 Linux） | 云端 + 自研模型 |
| VoiceInk | ⚠️ 买断 29/49/69 美元 | 仅 macOS | 本地 Whisper + BYOK |

这一类**用电脑的麦克风**，覆盖的是"电脑有可用麦克风、且愿意装东西/下模型/订阅"的人。

### 3.2 主流形态二：手机当电脑麦克风（只给音频）

- **WO Mic**（⚠️ Google Play 500 万+ 安装、4.0 星、1.76 万条评价）：Wi-Fi/蓝牙/USB 把手机变成电脑麦克风。
- 它的头号差评是"手机息屏后自动断开"（省电机制）——正是我们在续连/判活上花了好几轮的同一个问题。
- **它给的是音频**，拿到之后还得自己找 PC 端识别。我们相当于把这一级和上一级合并成一步。
- **[MicYou](https://github.com/LanRhyme/MicYou)**（✅ 2026-09 核实仓库页：3.9k stars、GPL-3.0、Android 原生客户端 + Windows/Linux/macOS 服务端、WiFi/USB/手机网页扫码三种连接、带 AI 降噪与回声抑制）：把手机做成电脑的虚拟麦克风设备。**它是这一格里规模最大的开源项目**——说明"手机当麦"不是我方独有认知，但它的路径仍是只给音频、识别在电脑侧解决。

### 3.3 主流形态三：硬件语音键鼠（中国市场的付费证据）

- **讯飞智能语音鼠标/键盘**：⚠️ 99 元～699 元、语音约 400 字/分钟、宣称 98% 准确率、部分型号内置离线语音引擎。
- 价值在于**证明中国用户愿意为"在电脑上说话出字"直接掏钱**，只是他们选的形态是"买个鼠标"，而且识别用的是讯飞自己的引擎。

**这一格的共同特征（2026-09 重核后已部分失效）**：PhoneMic / AirType / CatDB 确实都是**个人项目、几十颗星、Windows 优先、手机端是网页、没有签名与正经分发**——但这几条已经不是这一格的全貌：**AirMic** 覆盖 Linux（含 Wayland）/macOS/Windows，**仓鼠口袋键鼠**是公司主体运营、有 ICP 备案、安装包分发、账号 + 订阅。也就是说，"竞品都很弱、都没做正经分发"这个自我安慰**不再成立**。

**CursorLink（✅ 2026-09-22 抓官网全文；同形态里唯一一家已商业化、且走云端中转的产品）**：上海尺锋网络科技有限公司（沪ICP备2026000234号-2，备案号是 2026 年的）。Windows 10/11 客户端约 4MB、macOS 12+ 约 8MB（**客户端版本只有 0.1.0**）、安卓 App（1.0.11）、以及**微信小程序**。**没有 Linux。**

- **机制：模拟键盘注入，而且把"0 剪贴板污染"做成了首页的一格数据。** macOS 的 FAQ 自己写明"需要辅助功能权限才能**模拟键盘输入**"（该软件**未做 Apple 签名**，首次安装要手动授权）。注意区分：它模拟键盘把**内容本身**注入，我们是模拟 Ctrl+V、内容走剪贴板。⇒ 它正好验证了我们上一轮识别出的那条**唯一技术倒退：剪贴板被污染**——而且它把这件事当卖点讲。
- **走云端中转**：FAQ 明确"**不需要**手机和电脑在同一网络"，通过**云端中转服务器**传输，支持跨网络、跨地域；宣称"端到端加密、不存储任何输入内容"。⇒ 这是我们主动放弃的那根轴，**已有第三个玩家在用**（仓鼠、CursorLink）。
- **商业模式：文字免费，图片/文件传输与 AI 功能要会员。** ⇒ 与我们"文本与图片永久免费、不做付费墙"**相反**；但它同时验证了我们的另一条原则——**付费墙不切在核心流程（文字输入）里**。
- **多设备**：一个小程序可绑定多台电脑、随时切换、配对码一键连接。⇒ 我此前提过的"设备位"方向，它已经这么做了。
- **两条我们没做的**：`/transfer/` 免下载的"临时传输"网页模式；`/ai-suiji/`「AI 随己」——把语音记下的想法交给 AI 整理成"数字分身"。
- **它的主推场景是"AI 协作"**（ChatGPT / Claude / **Cursor** / Copilot）与代码注释——名字里的 Cursor 就是这个意思（即上一轮从 AgentVoice 看到的那个新分支的商业化版本）。
- **⚠️ 早期迹象**：客户端才 0.1.0；官网说"支持 Windows、macOS 双平台"，FAQ 却说"macOS 12+ 即将推出"（自相矛盾）；macOS 未签名。⇒ 它有没有真实用户、留存如何，**无从判断**。

**三个结论**：
1. **思路不新鲜**——"手机输入法识别率更高"是共识（AirType 的 README 明写；CatDB 就是因为"豆包输入法 PC 版还没出"而生的）。我们能领先的不是想法，是**工程厚度与完成度**。
2. **我们多出来的东西**：绑定身份、断线续连、判活、自动粘贴 + 自动回车的**完整交付链**（它们都没做）；以及写**剪贴板 + 粘贴**而不是模拟按键"打字"——中文、emoji、长文本要可靠得多。
3. **"复用手机输入法"仍是独有壁垒**——连形态最像的 AirMic 都走浏览器 Web Speech API，拿不到手机输入法的词库、方言与惯用语；讯飞「跨屏输入」虽然与我们同源，但强制两端都装讯飞输入法。

### 3.5 免费替代（最容易漏掉的一格）：主流输入法自带的「跨屏输入」

**这一格不是产品，是功能——但它才是我们真正的价格天花板。**

- **讯飞输入法「跨屏输入」**（✅ 2026-09 核实）：电脑端和手机端**都必须装讯飞输入法**，两端同网（或登同一账号）→ 电脑端出二维码 → 手机扫码 → 手机输入法说话 → 文字进电脑。免费。有用户反馈偶尔断连。
  - **平台：Windows ✅ / macOS ✅ / Linux ❌。** 讯飞输入法 Mac 版明确把"跨屏语音输入／手机说话电脑打字"列为功能；**没有官方 Linux 客户端**，Linux 这一格是空的。
  - **实现机制（⚠️ 据其专利 CN112684995B「跨屏输入方法及装置」，2020 申请 / 2024 授权）**：扫码配对后**建立"跨屏会话"、把内容以应用层消息推给远端**，专利原文强调"无需输入法或第三方应用进行修改或适配"。⇒ **不经过剪贴板**（这点与我们不同），但也**不是模拟键盘注入**。它能落进任意应用，很可能正是因为它本身**占着 PC 端的输入法位置**（以 IME 提交的方式落字）——这也解释了它为什么必须在电脑上装讯飞输入法。
- **搜狗输入法**有类似能力，社区评价其准确率不如讯飞。
- **对我们的含义**：目标用户（已经习惯手机输入法语音的人）手里**可能已经有**这个东西，而且免费。所以"手机语音 → 电脑出字"这件事本身**不能作为付费点**；付费点必须落在讯飞做不到的地方——**PC 端什么都不装（不用换掉你现在的电脑输入法）、手机用什么输入法都行、文本不经过任何第三方服务器**。

**⚠️ 我们和讯飞不是"谁更强"，是技术取舍不同：**

| | 讯飞跨屏输入 | 我们 |
|---|---|---|
| PC 端前提 | **必须装讯飞输入法并切到它**（要放弃你现在的输入法） | 不碰你的输入法，只跑一个小程序 |
| 手机端来源 | 必须也是讯飞 | 任意输入法（豆包 / 微信 / 搜狗 / 系统自带都行） |
| 文字如何落地 | 应用层会话推送，**不碰剪贴板** | **写剪贴板 + 模拟 Ctrl+V**（终端自动切 Ctrl+Shift+V） |
| 平台 | Windows、macOS | Windows、macOS、**Linux X11**（Wayland 除外） |
| 代价 | **Linux 没有**；两端都被讯飞锁住 | **污染剪贴板**（每说一句就替换掉你的剪贴板）；需要时序余量（写剪贴板后 50ms、回车前 250ms 起）；Windows 受 UIPI 限制进不了更高权限窗口；**Wayland 不支持**，回退纯剪贴板 |

**为什么只能这样选：把文字送进光标处只有三条路，每条各交一种税。**

| 路线 | 谁在走 | 它交的税 |
|---|---|---|
| 剪贴板 + 模拟 Ctrl+V | **我们** | **污染用户剪贴板** + 应用异步读剪贴板的时序复杂度（我们代码里 50ms / 250ms 的余量就是给这个的） |
| 模拟键盘把内容本身注入 | **CursorLink**；PhoneMic / AirType 及 Cross-Screen 那类也是 | **长文本可靠性**（掉字 / 错序 / 被输入法截进候选框），焦点不对就失败 |
| 走 PC 输入法的提交通道 | **讯飞「跨屏输入」** | **必须在电脑上装它的输入法**（要放弃你现在的输入法） |

⇒ **第三条对我们不可用**——"不装任何 PC 端输入法"正是我们的卖点。所以我们实际只能在"剪贴板"和"键盘注入"之间二选一：**"零剪贴板污染"不是白捡的升级，是一次换税**（拿剪贴板污染去换长文本可靠性风险）。而**讯飞那条是三条里唯一两条税都不交的**——不污染剪贴板、也不需要逐字注入，因为它占着输入法位置。这就是它作为免费替代最硬的地方。

**键盘注入这条路的优劣（把剪贴板污染那一条抛开不看）**：它的**内容保真能力按平台递减**——macOS 最好（`CGEventKeyboardSetUnicodeString` 是一等 API，直接塞字符串），Windows 次之（逐 UTF-16 单元，emoji 这类代理对与组合序列有风险），**Linux X11 最差**（中文靠临时改写键盘映射，逐字注入，emoji 甚至可能拿不到 keysym）。内容之外它还有三处结构性劣势：

1. **换行没有通用解**——`\n` 映射成 Enter 会变成"边注入边发送"、把一段话拆成多条；映射成 Shift+Enter 又只在聊天软件里成立（编辑器、终端里都不是换行）。而剪贴板路线天然绕开了这个问题：换行是**内容的一部分**，"发送"是另一个独立动作。
2. **副作用**——逐字注入是一串**真实键盘事件**，会触发目标应用的自动补全、自动配对括号、自动缩进、代码片段展开，以及输入法的候选/联想；粘贴则是**一次原子事件**，不触发这些。
3. **失败不可恢复**——剪贴板路线失败时文字还在剪贴板里（用户自己 Ctrl+V 就能救），注入失败则文字既没进光标处、也不在任何地方，只能重说。

它胜出的地方只有两条：**剪贴板不被污染**（它唯一的宣传优势），以及**终端天然支持**（逐字在 vim / ssh / cmd 里通用，可以删掉我们那张 20+ 类名的终端特判表）。

⇒ **综合看：抛开污染这一条，现有剪贴板路线在体验上更优。** 另外值得注意的是，**注入质量最好的平台是 macOS、最差的是 Linux X11**——这与"开发者自己主要在 Linux 上用"的主平台恰好相反。

**顺便否掉一条看上去聪明的路**：既然我们无法避免写剪贴板，那"写完再把我们塞进去的内容删掉"行不行？**不行。** 删除不等于恢复——用户原来的内容在我们写入的那一刻就已经没了，删掉之后剪贴板是**空的**，不是"原样"；而且清空会打破"剪贴板就是兜底、粘贴落空还能 Ctrl+V 救"这条设计不变量（失败就从"可恢复"变成"彻底丢失"），还多一个**不可观测的竞态**（清早→目标应用还没读完剪贴板，粘贴变空；"读完了"没有任何事件可等，我们现在的 50ms / 250ms 就是硬等出来的）。更根本的是：剪贴板管理器（Win+V 历史、Klipper / GPaste / CopyQ、macOS 的 Maccy）在我们写入那一刻就把内容记走了，事后清空**连"零污染"都支撑不起来**。真正的解只有两条：**保存-恢复**（写入前读走、粘贴后写回）或**根本不写**（改走键盘注入，即上表第二种税）。

⇒ 一句话：**我们用"剪贴板被污染 + 时序复杂度"，买到了"不占用你的电脑输入法 + 不挑手机输入法 + 有 Linux"。不是实现更强，是约束更少。**

## 4. 我们凭什么（差异化）

1. **跨生态**：任何安卓手机 + 任何 PC（Windows/macOS/Linux）。手机厂商的多设备协同只服务自家生态，这是它们结构性做不到的地方。
2. **电脑端零条件**：不装输入法、不下模型、不买硬件、不用管麦克风好坏。
3. **识别质量来自手机输入法**：用户自己的词库、方言、惯用语都在那儿，比电脑上现装的小模型更懂他。
4. **工程厚度**：绑定/续连/判活/自动粘贴/自动回车的完整链——同类个人项目都停在这一层之前。
5. **交付方式稳**：文字先落剪贴板再谈自动粘贴，剪贴板是所有桌面环境的最低公约数。
6. **可验证的隐私**：零云端；若核心开源，这句话是**可被验证**的，而不是一句声明。
7. **手机端是原生 App，不是一个网页**（同类里除 CursorLink 外，PhoneMic / AirType / CatDB / Cross-Screen / AirMic 的手机端**都是网页**）。这不只是观感：**网页拿不到输入法的 composing（正在输入）状态**，所以"松手即发"这个手感、以及按段提交的判断都做不出来；相机扫码、被杀后台后的续连、剪贴板兜底同样都依赖原生能力。⇒ 手机端的体验差距是**结构性的**，不是打磨出来的。

**⚠️ 要打"隐私"这张牌之前，先把所有隐私面审一遍——不能只修剪贴板。** 四个面：

1. **PC 端日志会不会打印正文？**（最容易被忽略，也最容易在自己的机器上查。日志里有正文的话，"不留痕"就是自欺。）
2. **临时连接的传输是否加密？** 在别人的网络里，同网段的人能不能嗅到载荷？（配对码与凭证校验只解决"谁能连"，不等于载荷保密。）
3. **在别人电脑上留下了什么状态？** 临时连接结束后，那台 PC 上还留着席位 / 凭证 / 设备记录吗？**如果它还记着"这台手机连过这台电脑"，那比剪贴板更严重**——"用完就走"必须是真的。
4. **手机端将来存历史吗？**（第 5 节第 3 项要做）那也是持久存储，只是手机属于自己、风险等级低一些。

**这四条里任何一条不干净，"隐私"这张牌就打不响**；而其中第 2、3 条的后果可能比剪贴板更严重。**"我们比讯飞、CursorLink 更懂隐私"这句话，得先经得起这四条自查**——而且这正是我们相对它们的结构性优势所在：它们的隐私是**承诺式**的（端到端加密、我们不存储——但文字必须经过它的中转服务器，你得相信它），我们的可以做成**结构性 + 可验证**的（数据根本不经过任何服务器 + 代码可查）。

   - **真正满足该诉求的只有键盘注入**（完全不写剪贴板）。**一个有利的对齐**：别人的电脑几乎必然是 **Windows / macOS**——恰好是注入质量最好、且 enigo 已实现 `fast_text` 的两个平台；而注入最差的 **X11 正是他自己的常用机**，那里并不需要隐私模式 ⇒ **技术上可以不做 X11 注入。** 但**他只能在自己拥有、且能真机验证的平台上做**（红线：先真机验证再发版）——有没有 Windows 机器可用于验证，决定这条路现在能不能走。
   - **前置条件**：注入失败不可恢复 ⇒ **必须同时有手机端历史 / 重发（第 3 项）**。
   - **✅ 2026-09-23：X11 部分已实现并真机验证**——做法不是标记、也不是注入，而是**我们自己当剪贴板主人**：X11 的剪贴板是"所有权 + 按需提供"协议，数据始终在我们内存里，**在我们发出粘贴键之前一律拒绝读取**（剪贴板管理器正是在那一刻来抓的）⇒ 它的历史里没有；粘贴之后放行 ⇒ 目标应用拿得到、用户手动 Ctrl+V 也照旧（兜底不丢）。代码 `desktop/src-tauri/src/clipboard_x11.rs`，边界见 `TECH_DESIGN.md` §10.4（只在 X11 生效、只在"本轮真会发粘贴键"时接管、我们退出则内容消失、慢速管理器仍可能漏）。**这是 Windows/macOS 做不到的**（那两个平台的剪贴板是"写给系统"，只能靠官方标记请求对方放过）。**下一步**：Windows/macOS 的标记法（Windows 三个官方格式 + macOS `ConcealedType`）；Wayland 记入待评估（跟路线图第 5 项一起做）。
   - **呈现方式**：不要做成"技术二选一"，而是**按情境**——默认"我自己的电脑"（剪贴板，体验最好），另设一项**"在别人的电脑上使用 / 不留痕"**（注入）。用户该选的是他知道的情境，而不是他无法预判后果的技术权衡。

   - **三个档位（2026-09-22 补，回答"能不能既不留痕、又继续用剪贴板"）**：
     - **A 档｜根本不写剪贴板**（键盘注入）：唯一真正的零足迹。代价见前文（可靠性 / 失败不可恢复 / 换行无通用解）；**而且它不解决日志、传输、临时连接遗留这三个面** ⇒ **"换成注入"≠"隐私安全"**。
     - **B 档｜瞬态剪贴板**（写入 → 立即粘贴 → 随后恢复原内容）：暴露窗口从"永久"压到几十～几百毫秒，**能挡住"下一个用这台电脑的人 Ctrl+V 就看到"这个具体画面**，但**挡不住剪贴板管理器 / 剪贴板历史**（它们在我们写入那一刻就记走了）。工程增量极小（同属剪贴板路线，只多一步"撤"）；风险是撤早了会让粘贴拿到**原内容**（比空粘贴更糟），而这个时序**不可观测**。
     - **C 档｜X11 特有的"真零足迹剪贴板"**：X11 的剪贴板不是共享缓冲区，而是**"所有权 + 按需提供"**协议——数据只活在我们进程内存里，谁请求、给不给、给几次都由我们决定 ⇒ 可以做到**只服务一次、且只在我们注入 Ctrl+V 之后**，此前的请求（含剪贴板管理器在所有权变更时的抓取）一律拒绝。**这是三个平台里唯一能做到零足迹的实现**；Windows / macOS 的剪贴板是"推进共享内存"，只能停在 B 档。**讽刺的是：唯一能零足迹的平台（X11）恰恰是不需要隐私模式的那台机器。**
     - ⇒ 对"别人的 Windows / macOS 电脑"这个场景，真正的选择只有 **A 档**或 **B 档**——**B 是"防手滑"级别的隐私，A 是"防取证"级别的隐私。**

   - **补一档（2026-09-23 另一会话核实）：敏感标记法**——仍是剪贴板路线，但写入时**附带"机密"标记**，让系统与主流剪贴板管理器**不记录、不同步**：Windows 有三个官方格式（`ExcludeClipboardContentFromMonitorProcessing`、`CanIncludeInClipboardHistory=0`、`CanUploadToCloudClipboard=0`，见[微软文档](https://learn.microsoft.com/en-us/windows/win32/dataxchg/clipboard-formats#cloud-clipboard-and-clipboard-history-formats)；密码管理器与 Chrome 无痕模式都这么做）、macOS 有 `org.nspasteboard.ConcealedType`、X11 有 `x-kde-passwordManagerHint=secret`（Klipper 认）。**它正好把上面 B 档"挡不住剪贴板管理器 / 历史"这条补齐**（Windows/macOS 上），而且**保持剪贴板的全速与可靠、永不丢内容**（内容仍在"当前剪贴板"里，用户随时能 Ctrl+V）；**与瞬态剪贴板叠加**＝连"下一个用这台电脑的人"也挡住。⇒ 于是选择可以更简单：**标记法（覆盖历史与云同步）+ 瞬态/只服务一次（覆盖"当前剪贴板"）**，注入模式留给真正要"防取证"的场景。

## 6. 明确不做

**加功能的判据（2026-09-22）**：一个额外功能该不该做，不看它本身多有用，而看**"要用它的那一刻，如果没有会不会很难受"**——也就是它的缺席会不会在**核心流程内部**造成断裂。图片传输符合这条：动作是同一个（"我手机上有东西，想让它出现在电脑上"），只是内容从文字变成了图。

- **不自建语音识别引擎**——复用手机输入法，这是产品的地基。
- **不做云端中继**——纯局域网；跨网络（在外地用流量）不在产品范围内，因此也不为它引入账号与服务器。
- **不做账号体系**——收费走离线许可证；账号只在将来真有云功能时才有意义。
- **不做剪贴板/图片的历史管理**——那会把产品变成文件或剪贴板管理器，破坏"直达输入位置"的简洁模型。
- **不做通用文件传输**——图片是唯一例外。分界线不是文件格式，而是**图片是"输入"、文件是"附件"**：图片跟文字同级，走同一条"剪贴板 + 粘贴"通道、一个动作就完成；文件体积不受控，需要进度、失败重传、断点续传，那是 LocalSend 一类工具的活。（技术上"能接图片的输入框就能粘贴文件"基本成立——剪贴板里放的是文件路径——但这不构成该做的理由。）做了它，产品就从"直达输入位置"变成"文件传输工具"。
- **不做远程控制**（鼠标/键盘/屏幕）。
- **不做遥测**，不做打扰式更新提示。
- **不为"语音识别特性差的输入法"做按品牌适配**——改进放在与输入法无关的方向上（例如第 5 节的发送延迟）；差的输入法该被淘汰，我们只需不惩罚它。
- **不为不常见的问题加机制**。

## 7. 商业化：目前看不到收费路径

**2026-09-22 评估结论：在当前形态下看不到收费点，倾向"免费开源 + 接受捐赠"。** 三条理由：

1. **没有升级空间**——核心功能本身已经足够好用，谈不上"有什么高级功能比它更好用"。单点产品的升级空间来自"更多 / 更贵 / 更快 / 更省心"，这四样本产品都不需要。
2. **成本结构是零**（无云、无 GPU、无模型）⇒ 它不需要收入来存活，也就没有非收不可的理由。
3. **免费替代已经够多**——讯飞「跨屏输入」免费、Win+H 免费、同类 Handy / PhoneMic / AirType / CatDB 全是免费开源 ⇒ 收不到。

⚠️ 这个结论是在**零用户**的位置上得出的：**收费是分发之后才可能出现的问题**。若将来真有一群人用起来、并且反复要同一个"更多 / 更大 / 更好"，那时再重新评估——而不是现在去设计它。

**已经否掉的收费方向**（记下来，免得重走）：

- **走苹果开发者平台、只做 iOS / macOS 专属版**：(a) 输入注入类 Mac 工具很可能过不了 Mac App Store 审核（要"辅助功能"权限，App Review 按 Guideline 2.4.5 拒，剪贴板管理器有被拒的公开先例），现实路径是官网分发 + Developer ID 公证，**App Store 的收款通道帮不到桌面端**；(b) 会放弃需求最集中的 Windows 与安卓——同类产品全是 Windows 优先，而唯一可见的付费证据（讯飞语音鼠标）买的正是"Windows 电脑 + 安卓手机"这个组合。
- **设备位 / 限额类收费**：在"一部手机 + 一台电脑"的产品里，限制是人为造出来的，不成立。
- **⚠️ 后到的反证（2026-09-22，需他复核）**：**CursorLink**（同形态、已商业化的产品）做的是**文字免费 + 图片/文件传输收费（会员）**——与本节的"文本与图片永久免费"**相反**；**仓鼠口袋键鼠**也把图片/文件等捆进付费。⇒ **"图片该免费"不是市场共识**，这条判断目前的市场样本是空的、甚至反向的。原判断（图片属核心流程的补齐）暂时保留，但标注为**待他复核**。

**以下原则仅在"若将来真出现收费路径"时成立：**

- **文本与图片永久免费**：免费版就是完整可用的产品，口碑与传播靠它；隐私卖点靠"代码可见"来证明。
- **付费不切在核心流程内部**：图片传输属于**核心流程的补齐**（见第 6 节的加功能判据），因此**不做付费墙**。它跟文本桥是同一种价值——"把手机上的东西少几步弄到电脑上"，只是载荷从文字换成图；而且免费的替代品已经在用户手里（微信文件传输助手、LocalSend），痛点从来不是"做不到"，是"要四步"。⇒ 文本与图片都该在免费版里完整可用。
- **收费形态：一次性买断的离线许可证**——不做账号订阅（无服务器、不收集用户信息、心智简单）。
- **顺序**：先把核心体验（第 5 节 1–3 项）做扎实；iOS 适配与"是否收费"都在那之后再说。
